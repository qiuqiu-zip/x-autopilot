# 微调案例集（技术实施拆解） · 草稿（CASE1–CASE40，9/28，未发布）

> 定位：40 个微调项目的**技术实施全程拆解**（基座/数据/配置/坑/结果/成本）。
> 与行业案例集（商业视角）区分：本系列是工程视角的实操复盘。
> 案例为基于常见场景的示例拆解（参数与结果为典型值），实施前用自己的数据验证。

## 对话与客服类（CASE1–8）

### CASE1. ⚪ 案例：7B 客服话术微调全程

**任务**：电商售后客服的话术标准化。**基座**：Qwen 7B。**数据**：脱敏客服对话 1,200 条（用户问 + 标准回复对）。**配置**：QLoRA（r=16, alpha=32, lr=1e-4, 2 epochs）。**坑**：初版把多轮对话拍平成单轮，模型学不会接上下文——改成只对最后一轮算 loss 后解决。**结果**：话术风格一致性人工评分 3.2→4.5（5 分制）。**成本**：4090 租用 3 小时 ≈ $2。**复盘**：数据模板一致性比数据量重要。

### CASE2. ⚪ 案例：多轮客服的轮次设计

**任务**：客服多轮对话（处理追向和澄清）。**基座**：Qwen 14B。**数据**：2-5 轮对话 800 段。**配置**：QLoRA（r=32，多任务较复杂），只对 assistant 最后一轮算 loss。**坑**：上下文里塞了 10 轮历史，显存爆炸——历史摘要化后解决。**结果**：多轮任务完成率 61%→84%。**成本**：单卡 6 小时。**复盘**：多轮微调的数据构造成本是单轮的三倍，预算要提前翻倍。

### CASE3. ⚪ 案例：情绪识别的客服质检

**任务**：客服对话的情绪与合规质检（分类任务）。**基座**：Qwen 3B（分类任务小模型够）。**数据**：标注对话 3,000 条（合规/情绪/流程三类标签）。**配置**：LoRA 全层（r=8），3 epochs。**坑**：类别不均衡（合规违规只占 4%）——加权 loss + 过采样后宏 F1 从 0.71 到 0.86。**结果**：全量质检替代 5% 抽检。**成本**：本地 4090 半天。

### CASE4. ⚪ 案例：智能外呼的话术微调

**任务**：外呼机器人的话术自然化（机器人腔→人味）。**基座**：Qwen 7B + 语音合成。**数据**：真人销售录音转写 600 段。**坑**：文本微调后语音合成的停顿不自然——在文本里显式加入停顿标记后解决。**结果**：外呼完播率 23%→41%。**复盘**：文本微调和语音合成是两个模型——联调的坑比各自的多。

### CASE5. ⚪ 案例：工单分类与路由

**任务**：工单自动分类路由（12 类）。**基座**：3B 小模型。**数据**：历史工单 5,000 条。**配置**：LoRA（r=8），分类头微调。**坑**：长尾类别（每类不足 50 条）效果差——合并小类为"其他"+人工兜底。**结果**：top1 准确率 89%，路由人工工作量减 70%。**复盘**：分类任务的类目设计比模型选择重要——类目互斥才能分得准。

### CASE6. ⚪ 案例：客服知识库的联合优化

**任务**：RAG + 微调组合（客服场景）。**架构**：RAG 检索产品文档 + 微调模型统一口径输出。**数据**：微调数据 800 条（标准口径问答）。**坑**：RAG 检索的内容和微调口径冲突（模型更信微调的风格，篡改了检索的事实）——提示词里明确"事实以检索内容为准，风格按训练"后解决。**结果**：口径一致 + 事实准确双达标。**复盘**：RAG+微调的组合，冲突测试必须做。

### CASE7. ⚪ 案例：售前咨询的销售话术

**任务**：售前咨询的销售话术（不越界版）。**基座**：Qwen 14B。**数据**：合规话术 500 条 + 违规话术 300 条（对比训练）。**配置**：SFT + DPO 两阶段（DPO 数据：合规回复 vs 过度承诺回复对）。**结果**：违规承诺率 7%→0.3%。**复盘**：合规场景用 DPO 比纯 SFT 好——SFT 教"该说什么"，DPO 教"不该说什么"。

### CASE8. ⚪ 案例：跨语言客服的混合微调

**任务**：中英双语客服。**基座**：Qwen 14B。**数据**：中文 2,000 + 英文 800（配比 7:3 保通用能力）。**坑**：全中文数据训练后英文能力崩了（灾难性遗忘的双语版）——加英文通用数据混训后恢复。**结果**：双语客服上线。**复盘**：多语言微调的语言配比，是保住基座能力的旋钮。

## 文档与文本类（CASE9–16）

### CASE9. ⚪ 案例：合同风险条款识别

**任务**：合同风险条款标注。**基座**：Qwen 14B。**数据**：合同 + 法务标注 900 份。**配置**：LoRA（r=32，长文本任务）。**坑**：长合同（50 页+）超上下文——按条款切分逐段审查 + 汇总。**结果**：风险条款召回 92%（法务双人标注为基准）。**成本**：租 A100 2 小时 ≈ $8。**复盘**：长文档任务先设计切分，再设计训练。

### CASE10. ⚪ 案例：判决书要素提取

**任务**：判决书结构化提取（当事人/法条/判决结果）。**基座**：Qwen 7B。**数据**：判决书 2,000 份 + 结构化标注。**配置**：LoRA + JSON 输出微调。**坑**：判决书格式各地法院不统一——按法院分组增强数据后鲁棒性提升。**结果**：要素抽取 F1 0.91。**复盘**：格式多样的领域，数据覆盖的"格式多样性"比"数量"重要。

### CASE11. ⚪ 案例：会议纪要的自动化

**任务**：会议录音转写 → 结构化纪要（决议/待办/责任人）。**架构**：Whisper 转写 + 微调模型结构化。**数据**：转写文本 + 纪要对 400 份。**坑**：口语的冗余和跑题——训练数据里保留"口语原文"，模型学会从乱糟糟的口语里提取结构。**结果**：纪要初稿可用率 85%。**复盘**：口语到结构化的微调，数据里的"脏"不能洗——模型要学的是从脏到净。

### CASE12. ⚪ 案例：技术文档的问答对构建

**任务**：技术文档问答（内部 RAG 的微调层）。**数据**：文档切片 + 生成 QA 对 1,500 条（强模型生成 + 人工抽检 20%）。**配置**：LoRA。**坑**：合成 QA 对里 15% 的问题在文档中无答案——增加"无法回答"类样本，模型学会说"文档中未提及"。**结果**：幻觉率 31%→9%。**复盘**：**"拒答能力"也是可以微调出来的。**

### CASE13. ⚪ 案例：周报生成的翻译官

**任务**：git commit + 项目数据 → 周报。**基座**：Qwen 7B。**数据**：commit 历史 + 历史周报对 300 份。**配置**：LoRA（r=8）。**坑**：个人文风差异大——按人生成、按人存储，每个人的周报用自己微调的版本。**结果**：周报撰写时间 40 分钟→5 分钟。**复盘**：个人风格任务，"一人一模型"比"一模型服务所有人"效果好。

### CASE14. ⚪ 案例：简历初筛的合规版

**任务**：简历技能匹配（合规版：只评技能不评人）。**基座**：3B。**数据**：JD + 简历 + 匹配度标注 2,000。**配置**：分类微调。**合规设计**：删除性别/年龄/院校字段（只保留技能与经验描述）+ 输出不带人名（输出匹配度不输出排名）。**结果**：初筛时间 70%。**复盘**：合规不是事后过滤，是训练数据设计时就删掉敏感字段。

### CASE15. ⚪ 案例：法律翻译的术语强约束

**任务**：合同中英翻译（术语强一致）。**基座**：Qwen 14B。**数据**：双语合同 800 份 + 术语表 500 条（作为约束注入提示词）。**配置**：LoRA。**坑**：同一术语不同译法混训——术语表统一后一致性从 78% 到 97%。**结果**：翻译初稿 + 人工终审成为流程。**复盘**：术语一致性靠"数据一致性"，不靠模型自觉。

### CASE16. ⚪ 案例：企业知识库的口径统一

**任务**：企业内部问答的口径统一（不同部门对同一政策的说法不一）。**架构**：RAG（检索政策原文）+ 微调（统一表述口径）。**数据**：标准口径问答 600 条。**坑**：政策更新后旧口径数据要下架——数据集版本化管理后解决。**结果**：跨部门口径一致率 95%。**复盘**：口径类微调的数据有"保鲜期"，版本管理是运维的一部分。

## 代码与数据类（CASE17–24）

### CASE17. ⚪ 案例：代码评审助手

**任务**：代码评审助手（学会团队的评审标准）。**基座**：Qwen-Coder 14B。**数据**：历史 PR 的 diff + review 评论 1,500 对。**配置**：LoRA。**坑**：评审意见里"为什么"的缺失——数据清理时保留评审理由（不只保留改了什么）。**结果**：评审意见采纳率 68%。**复盘**：评审微调的数据质量，取决于历史 review 里是否保留了理由。

### CASE18. ⚪ 案例：SQL 生成助手

**任务**：自然语言转 SQL（内部数仓）。**基座**：Qwen-Coder 14B。**数据**：问题 + 正确 SQL + 表结构 1,200 对。**配置**：LoRA + 表结构注入提示词。**坑**：字段名是拼音缩写（内部黑话）——表结构文档微调进模型后准确率提升。**结果**：SQL 可执行率 74%→93%。**复盘**：内部黑话（字段名/表名）必须成为训练数据的一部分。

### CASE19. ⚪ 案例：测试用例生成

**任务**：单元测试用例生成。**基座**：Qwen-Coder 7B。**数据**：函数 + 测试用例对 2,000。**配置**：LoRA。**坑**：生成的测试有"永真"测试（断言恒真不算覆盖）——测试有效性校验（故意引入 bug 看测试能不能抓到）加入评测。**结果**：测试覆盖率 55%→81%，且有效性验证通过。**复盘**：代码生成的评测，"能跑"不够，要"有效"。

### CASE20. ⚪ 案例：日志分析的异常检测

**任务**：日志异常模式识别（运维）。**基座**：3B。**数据**：历史日志 + 异常标注 8,000 条。**配置**：分类微调。**坑**：日志格式五花八门——按服务分组训练（每个服务一个模式）。**结果**：异常检出率 82%，误报率 11%。**复盘**：日志微调的前提是日志规范化——脏日志先治理再微调。

### CASE21. ⚪ 案例：API 文档问答

**任务**：内部 API 文档问答（RAG + 微调）。**数据**：API 文档 + 历史开发者问答 900 条。**坑**：API 版本迭代快——文档版本戳 + 微调数据同步更新机制。**结果**：开发者问题自助解决率 64%。**复盘**：API 文档问答的运维成本主要在"版本同步"，不在训练。

### CASE22. ⚪ 案例：数据报表的口径统一

**任务**：报表口径的问答统一（"GMV 怎么算的"每次答案一致）。**数据**：指标定义文档 + 历史问答 500 条。**配置**：RAG + LoRA 双层。**结果**：口径问题的一致性回答率 99%。**复盘**：口径统一类任务，RAG（检索定义）+ 微调（统一表述）缺一不可。

### CASE23. ⚪ 案例：代码迁移助手（语言 A→B）

**任务**：旧语言到新语言的代码迁移。**基座**：Qwen-Coder 14B。**数据**：迁移对 800 对（旧代码 + 新代码）。**配置**：LoRA。**坑**：迁移不只翻译语法，还有惯用法（新语言的 best practice）——数据里包含迁移后的重构版本而非直译版。**结果**：迁移初稿采纳率 61%。**复盘**：代码迁移微调的数据，要用"迁移后的正确姿势"，不是"逐行翻译"。

### CASE24. ⚪ 案例：数据清洗脚本的自动化

**任务**：为不同格式的数据生成清洗脚本。**基座**：Qwen-Coder 7B。**数据**：脏数据样本 + 清洗脚本对 500 对。**结果**：数据清洗的脚本编写时间减 60%。**复盘**：元任务（生成工具的 AI）的微调，训练数据来自"过去手动干的活"——**你工作的历史，就是微调的数据集。**

## 专业领域类（CASE25–32）

### CASE25. ⚪ 案例：医疗分诊的合规落地全程

**任务**：分诊引导（合规版）。**基座**：Qwen 14B。**数据**：分诊对话 1,500（脱敏）。**合规三件套**：训练数据删诊断结论（只留科室推荐）、输出模板带免责声明、紧急症状关键词强制急诊路由。**坑**：模型偶尔"热心"给用药建议——DPO 负样本（用药建议类回复）压制。**结果**：科室推荐准确率 88%，零诊断输出。**复盘**：医疗微调的合规成本 ≈ 技术成本——但合规就是入场券。

### CASE26. ⚪ 案例：医保政策问答

**任务**：医保政策问答（本地 RAG + 微调）。**数据**：政策文档 + 问答对 700。**坑**：政策的地域差异（各市规则不同）——按地区路由 + 分地区数据。**结果**：政策问答准确率 91%。**复盘**：政策类问答的"地域路由"是被忽略的架构设计。

### CASE27. ⚪ 案例：医学文献的科普转译

**任务**：医学论文 → 患者科普。**基座**：Qwen 14B。**数据**：论文 + 科普版对 400。**配置**：LoRA。**坑**：科普的"度"（通俗但不失准确、不产生误解）——医学顾问参与的评测集把关。**结果**：科普审核通过率 82%。**复盘**：科普转译的评测必须领域专家参与——通用评测测不出"医学上误导"。

### CASE28. ⚪ 案例：保险条款问答

**任务**：保险条款的人话翻译。**基座**：Qwen 14B。**数据**：条款 + 人话解释对 600。**合规**：解释 ≠ 承诺（输出模板规避赔付承诺）。**结果**：条款类咨询自助解决率 71%。**复盘**：金融保险类微调的输出，全部走合规模板套壳。

### CASE29. ⚪ 案例：财报问答的口径引擎

**任务**：财报数据问答。**架构**：Text-to-SQL + 微调口径解释。**数据**：财报问题 + SQL + 口径说明 800。**结果**：数据类问题自动应答 76%。**复盘**：金融数据问答 = 取数（SQL）+ 解读（口径）两层，微调主要优化解读层。

### CASE30. ⚪ 案例：投教内容的分层生成

**任务**：投资者教育内容（按知识水平分层）。**基座**：Qwen 7B。**数据**：同主题三层深度内容对 400。**合规**：教育内容不涉及标的推荐（模板规避）。**结果**：内容产能 ×6，合规零事故。**复盘**：合规敏感行业的内容微调，模板规避 + 数据洁癖是两条命。

### CASE31. ⚪ 案例：反欺诈话术的识别

**任务**：诈骗话术识别（客服对话里的风险信号）。**基座**：3B。**数据**：标注对话 4,000。**结果**：欺诈识别 F1 0.89。**复盘**：反欺诈的文本微调，数据里必须有**最新的诈骗剧本**——骗术在进化，数据要月更。

### CASE32. ⚪ 案例：制裁名单的合规筛查

**任务**：交易对手的制裁名单筛查（合规）。**基座**：3B + 规则引擎混合。**数据**：名单匹配样本 + 模糊匹配标注 2,000（制裁名单的翻译变体/缩写）。**结果**：模糊匹配召回 96%。**复盘**：制裁筛查的难点不是分类，是**变体识别**（同一个实体的一百种写法）。

## 生活方式与创意类（CASE33–40）

### CASE33. ⚪ 案例：个人助理的隐私微调

**任务**：个人助理（日程/邮件/笔记整理）。**基座**：Qwen 7B 本地。**数据**：个人数据（邮件草稿对 300、日程处理样本 200）。**架构**：本地 QLoRA + Ollama 部署——**数据全程不出本机**。**结果**：个人邮件草稿采纳率 70%。**复盘**：个人数据的微调，本地化部署是隐私的唯一解。

### CASE34. ⚪ 案例：写作风格的克隆实验

**任务**：写作风格克隆（用自己 100 篇文章微调）。**基座**：Qwen 14B。**数据**：文章 100 篇。**配置**：LoRA（r=16）。**结果**：盲测中 60% 的段落被认出是"我的风格"（vs 20% 基线）。**诚实结论**：风格学到了七成，观点和经历学不到——克隆体适合放大产量，不适合替代本人。

### CASE35. ⚪ 案例：翻译风格的驯化

**任务**：翻译风格驯化（消除翻译腔）。**数据**：双语对照 + 精修版 500。**结果**："翻译腔"盲测识别率下降 45%。**复盘**：翻译微调的本质是"教模型目标语言的母语者习惯"——精修版和机翻版的对比数据是关键。

### CASE36. ⚪ 案例：播客的 AI 制作管线

**任务**：播客制作管线（非微调，但相关）。**架构**：选题（LLM）→ 大纲 → 录音 → Whisper 转写 → AI 剪辑点标记 → shownotes 生成。**结果**：单集制作 8h→3h。**复盘**：管线里 AI 干"准备和整理"，人干"录制和观点"——分工清了，产能就来了。

### CASE37. ⚪ 案例：短视频脚本的爆款结构学习

### CASE61. ⚪ 案例：物流地址的智能纠错

物流行业的小痛点，微调的舒适区：**收派地址的自动纠错**。

场景：用户填写的地址千奇百怪（"朝阳区那个蓝色的楼旁边"），传统规则引擎改不动，人工确认成本高。微调方案：用历史工单（错误地址 → 正确地址的配对）训练小模型，输出结构化的纠错建议。

实战数据区间：地址纠错类微调的准确率通常能做到 90%+（模式高度固定），人工确认量降 60% 以上。

选它的原因讲给决策者：**数据现成**（历史工单就在库里）、**验收客观**（改对没改对一目了然）、**风险低**（建议制，人最终确认）——教科书级的第一批微调场景。

### CASE62. ⚪ 案例：制造业工单的缺陷分类

制造企业的售后工单分类，微调的第二个舒适区：

场景：设备报修工单里，"异响、漏油、报警码 E-XX"这类描述需要归类到具体缺陷原因，老师傅看一眼就知道，新人要翻手册。

方案：历史工单（已由老师傅标注过原因）微调一个小分类模型，新人提交工单时实时给分类建议。

关键经验：**缺陷描述的行业黑话是通用模型的最大短板**（"矿上那个三号皮带又打滑了"），恰恰是微调最大的甜点——用工厂自己的历史工单教出来的模型，黑话即母语。

落地提醒：产线术语更新快（新设备新型号），设计好"新类别"的数据回流通道，别让模型停在一年前。

### CASE63. ⚪ 案例：酒店点评的回复助手

连锁酒店的点评回复，一个量大战胜质的服务场景：

痛点：一个连锁品牌每月几千条平台点评，客服回复的质量参差（复制粘贴感重，差评回复火上浇油）。

方案：微调学习"品牌语气的回复范式"——好评的谦逊、中评的引导、差评的共情+解决路径，输入点评内容输出定制回复草稿，人工过目后发布。

效果的关键不在"写得多好"，在**语气一致性**：品牌声音从"每个客服一个样"变成"统一的人格"——这是通用 prompt 做不到的（它记不住你的 500 条历史优秀回复）。

数据准备：挑历史回复里转化效果最好的 2000 条（有后续入住的），比全量数据效果更好——**质量标注可以用业务结果反向做**。

### CASE64. ⚪ 案例：招聘简历的初筛助手

招聘简历初筛，微调的合规敏感型案例：

场景：HR 每天几百份简历，初筛标准其实很"行话"（这个学校的这个专业往届留存好、这段空窗期需要追问）——这些隐性判断标准，通用模型学不到。

方案：用历史简历（入职表现回填标注"这个候选人最终干得怎么样"）微调初筛模型，输出"匹配度 + 值得面试的理由 + 建议追问点"。

**必须写进方案的红线**：模型只能做"建议排序"，不能自动淘汰——历史数据里可能藏着偏见（性别、年龄、学校的隐性歧视），微调会忠实学习它们，自动淘汰等于把偏见规模化。

正确姿势：AI 扩大入围池（多看 30% 的简历），人做所有否决——**效率给人，公平也给人**。

### CASE65. ⚪ 案例：在线教育的作业批改反馈

作业批改反馈，教育场景的微调案例（守住边界的那种）：

场景：老师批改作业的时间大头不是"判对错"（客观题机器早就能判），是**写有针对性的反馈**——这道错在哪、下一步练什么。

方案：微调学习老师的历史批语风格（怎么鼓励、怎么指出问题、怎么给下一步建议），输入学生作业输出反馈草稿，老师修改后下发。

边界设计（教育场景的生死线）：反馈只针对**解题过程与方法**，绝不代做评价性结论（"你不适合学这个"类）；负向反馈一律软化改写，最终判断永远在老师。

家长侧的透明度：告知"AI 辅助、老师审核"的机制——**透明是教育场景信任的唯一来源**。

### CASE66. ⚪ 案例：图书出版的审校助手

出版行业的审校，一个"错误零容忍"的高标准微调案例：

场景：书稿审校查错别字、语法、体例（标点规范、数字用法、译名统一），资深审校稀缺且贵，新手漏检率高。

方案：用出版社的历史审校记录（错误 → 修改的配对语料）微调校对模型，输出"疑似问题清单 + 依据的规范条目"，审校确认。

这个案例的特别之处：**查全率比查准率重要**——多报几个误报审校扫一眼就过，漏一个错直接进书店。所以微调时的训练目标要向"宁可误报"倾斜（调整判定阈值，而不是追平衡指标）。

不同场景的不同指标取向，是微调工程里最容易被忽略的决策点。

### CASE67. ⚪ 案例：专利权利要求的结构化摘要

专利代理行业，微调的高价值场景：

场景：专利文献的权利要求书是高度格式化的法律文本，检索和对比时需要结构化摘要（保护范围、技术特征、引用关系）——人工摘要一份 30-60 分钟。

方案：用代理所的历史摘要微调，输入权利要求输出结构化卡片（技术领域/核心特征/独立权利要求要点）。

行业甜点：**格式极强 + 历史语料天然存在 + 从业者时薪高**（省下的都是真金白银），三个条件齐了，ROI 算得非常漂亮。

一个业务提醒：摘要可以 AI，但法律意见（这个专利能不能授权）绝对不能 AI——**文档加工可以自动化，法律判断必须留人**，这条边界写进客户合同里。

### CASE68. ⚪ 案例：环保排放报告的异常识别

环保合规场景，微调的"哨兵"型案例：

场景：工厂的排放监测数据（每小时一条），人工巡检只能抽查，超标往往事后才发现。

方案：用该厂/该行业的历史数据（正常波动 + 已确认的异常事件）微调异常识别模型——它学的不是通用统计，是**这家厂自己的"正常长什么样"**（季节波动、检修周期、设备特性）。

为什么微调优于通用方案：排放数据的"正常"因厂而异，通用阈值模型误报成灾——**每家厂自己的历史，就是最好的训练集**。

部署提醒：异常识别是"报警器"不是"判决书"——报警后必须有人的核查流程，别让模型直接触发处罚动作。

### CASE69. ⚪ 案例：体育赛事实时数据卡片

体育内容运营，微调的"模板学习"型案例：

场景：赛事直播时需要实时数据卡片（球员本轮数据、历史对比、里程碑提示），人工整理跟不上节奏。

方案：微调学习历史数据卡片的**叙事模板**（怎么把"球员第 3 次单场 30+10"写成一句有张力的话），输入结构化数据输出成品文案。

这个案例的技术特点：数据是结构化的（不缺），缺的是**把数字变成故事的表达层**——纯模板太死板，通用模型太飘，微调正好卡在中间：学会"这家媒体的腔调"。

时效是生命线：直播场景延迟超过 30 秒内容就没价值，**推理速度是硬指标**，模型选型时速度权重高于质量一档。

### CASE70. ⚪ 案例：博物馆展品讲解的多层生成

文博场景，微调的"分层输出"案例：

场景：同一件展品，讲解词要分三层——儿童版（故事化）、普通观众版（脉络化）、专业版（考据化），人工写三层成本三倍。

方案：微调学习馆方的讲解风格与史实边界（**史实不许编是底线**），输入展品资料，指定层级输出讲解稿。

技术要点：展品数量有限（几百件），史实核对可以做得极重——每条讲解都挂引用（哪本图录哪页），**宁可不输出，不可编史实**。

意外收获：讲解词的儿童版成了博物馆短视频的现成脚本——一份微调，两个渠道。

### CASE71. ⚪ 案例：判例类案检索的摘要助手

法律科技的微调案例（判例检索方向）：

场景：律师找类案（相似判例）时，读判决书全文太慢，需要快速掌握"裁判要旨、争议焦点、判决结果"——判决书平均上万字。

方案：微调学习法律文书的摘要规范（律所自己的摘要模板 + 历史检索笔记），输入判决书输出结构化检索卡片。

和法律意见的边界（重申 CASE67 的原则）：摘要严格限定"判决书里写了什么"，不做"这个案子该这么判"的延伸——**摘要是复制，意见是创作，前者可自动化后者不可**。

数据优势：判决书是公开语料，律所的摘要笔记是私有金矿——两者配对就是现成训练集。

### CASE72. ⚪ 案例：航运提单的信息抽取

国际贸易场景，微调的"单据结构化"案例：

场景：提单、报关单、发票的单据字段抽取（收发货人、货描、件数、毛重），格式五花八门（扫描件、传真件、各国模板），人工录入慢且错。

方案：用历史单据（已录入系统的"图 + 结构化数据"配对）微调抽取模型，新单据上传直接出结构化字段，置信度低的字段标红人审。

行业的真实痛点：**一个字录错，货卡在港口**——所以和出版审校相反，这个场景要"查准优先"（置信度阈值调高，宁可多人审，不可错放行）。

配套建议：错单回流机制——人工纠正过的字段自动进训练集，模型越用越准，**错误本身变成资产**。

### CASE73. ⚪ 案例：电商客服的退款话术升级

电商客服的退款场景，微调的"话术博弈"案例：

场景：退款咨询是客服最难的对话——既要安抚（防差评），又要合规（不能乱承诺），还要挽留（降退款率），话术分寸极难拿捏。

方案：微调学习"挽留成功的对话"（历史对话里最终用户撤回退款/接受替代方案的那些），生成符合平台规则的挽留话术。

一个必须守的合规红线：**挽留话术不能涉及虚假承诺**（"肯定能修好""必退不误"）——训练数据要先清洗，把历史对话里的违规承诺剔掉，**别让模型学会过去的错误**。

效果指标用业务说话：挽留率 + 差评率 + 合规抽查通过率，三个一起看。

### CASE74. ⚪ 案例：音乐版权的相似度初筛

版权行业的微调案例（歌词/文案的侵权初筛方向）：

场景：新歌上线前的版权自查（歌词和已有作品是否高度相似），人工比对慢且漏。

方案：这个场景的微调重点不是生成，是**判断**——用历史侵权判例（法院认定的"实质性相似"对 vs 未认定的相似对）微调相似度模型，学习"法律意义上的相似"而不是"字面相似"。

这个案例的启示：**"相似"的定义由行业历史决策定义**——法院判例教出来的模型，比通用的文本相似度（cosine）准一个时代，因为后者不知道"借鉴"和"抄袭"的边界在判例里。

输出定位：初筛报告（风险分级），最终法律意见还是律师的——和所有法律场景一个边界。

### CASE75. ⚪ 案例：游戏客服的外挂举报初筛

游戏运营的微调案例（举报分诊方向）：

场景：外挂举报每天几千条（视频、描述、截图），人工分诊慢，真外挂处理不及时破坏公平性，误伤正常玩家更糟糕。

方案：微调学习历史举报的处理结果（确认外挂/误报/无法判定），输入举报内容（玩家描述+行为日志特征）输出分诊优先级。

这个案例的技术特点：**信号是多模态的**——文字描述 + 行为数据（移速、命中率曲线），多模态数据的配对质量决定上限。

游戏行业的独特考量：**外挂手法迭代极快**（每周出新），模型必须月更——一个"训练一次管三年"的方案在游戏行业不存在，设计时就按"持续训练"的预算报。

### CASE76. ⚪ 案例：婚庆方案的个性化生成

婚庆行业，微调的"审美一致性"案例：

场景：策划师写方案（流程+文案+预算分配），每对新人都要定制，加班是行业常态。

方案：微调学习策划公司的历史方案——**不是学模板，是学"什么预算配什么配置、什么主题配什么文案调性"的决策模式**，输入新人需求问卷输出方案初稿。

有趣的训练数据问题：历史方案里藏着**过时的审美**（三年前的流行元素）——数据清洗时要按时间加权，**最近的方案权重更高**，别让模型把新人带到旧时尚里。

交付形态：方案初稿 + 可视化预算表，策划师的核心时间留给"面对面的定制沟通"——**把加班消灭在初稿环节**。

### CASE77. ⚪ 案例：车险定损的辅助描述

车险定损，微调的高风险高价值案例：

场景：查勘员现场拍照后要写定损报告（损失部位、维修方案、金额估算），新手报告反复被复核打回。

方案：微调学习历史定损报告（照片组 + 终审通过的报告），输入现场照片输出报告草稿和维修项目建议，查勘员核对修改。

风险等级说明：定损金额直接连着赔付，**这个场景的模型是"草稿员"不是"定损员"**——金额估算只能做参考区间，最终金额必须人工确认并留痕。

最有价值的训练数据不是正常件，是**被复核驳回的件**（初稿错在哪、终稿怎么改）——错误配对的数据，比正确配对教得更深。

### CASE78. ⚪ 案例：建筑图纸的变更摘要

建筑行业的微调案例（变更管理方向）：

场景：工程图纸一代代改（设计变更单 + 修订版图纸），现场工程师要快速知道"这版改了哪几处、影响哪些工序"——人工比对一版要半天。

方案：微调学习历史变更单的表述模式，输入新旧版本的差异信息输出人话版变更摘要（改了什么、影响什么工种、注意事项）。

行业甜点：变更单的写法高度行业化（术语+格式固定），**通用模型读不懂"三号楼基础垫层 C15 改 C20"意味着什么**——行业语料教出来的模型才接得住。

落地形态：摘要挂在项目管理系统的变更流里，自动推送给相关工种的负责人——从"等人发现"到"主动送达"。

### CASE79. ⚪ 案例：期货研报的观点提取

金融研究的微调案例（观点提取方向）：

场景：每天几百份研报，投研人员要快速提取"谁、对什么品种、什么方向、什么逻辑、多确定"——人工读不过来。

方案：微调学习投研团队的观点卡格式（品种/方向/核心逻辑/置信表述/时间窗口），输入研报输出结构化观点卡，汇入团队的信号池。

金融场景的两条铁律：**只提取不推荐**（模型复述研报观点，绝不生成投资建议——合规红线）；**带出处**（每张观点卡挂原文段落，可回溯核对）。

数据的坑：研报的立场和后验结果可以配对（这个观点后来对了吗）——但**用结果回填标注时小心幸存者偏差**（公开研报只是发表的，没发表的错误观点你看不到）。

### CASE80. ⚪ 案例：物业报修的智能分派

物业场景，微调的"分派路由"案例：

场景：业主报事报修（漏水、电梯、噪音……），人工分派慢且常有分错工单的（水电问题派给了保洁）。

方案：微调学习历史工单的分派记录（描述 + 实际派给谁 + 处理时长），新工单进来直接给"派单建议 + 紧急度评级"，物业客服一键确认。

小场景的大学问：**紧急度分级比分类更值钱**（漏水是十分钟级，噪音是当天级）——历史数据里"实际处理时长"就是免费的紧急度标注。

这类场景的推广路径：一个小区验证后，物业集团的横向复制几乎是零边际成本——**同构场景的集团化复制，是微调项目摊薄成本的唯一正道**。

### CASE81. ⚪ 案例：跨境电商 Listing 的本地化

跨境电商，微调的"多语言商业文案"案例：

场景：商品 Listing 的多语言本地化（标题、卖点、描述），机器翻译硬伤多（不懂品类黑话和平台规则），本地写手贵且慢。

方案：微调学习"平台优秀 Listing 的本地化范式"——目标市场的爆款文案结构、品类词汇、平台合规词表，输入中文源 Listing 输出地道的目标语言版本。

和通用翻译的本质区别：**本地化是"重新写"不是"翻译"**——德国站的 Listing 结构和美国站完全不同，微调学的是"当地怎么卖"不是"字怎么翻"。

合规附件：各平台的违禁词表直接做进输出的过滤层（医疗宣称、绝对化用语）——**合规词表 + 微调模型，缺一不可**。

### CASE82. ⚪ 案例：中医方剂的配伍提醒（边界案例）

一个刻意选的边界案例：中医辅助场景——**用来演示"什么时候不该微调"**。

设想的需求：方剂的配伍禁忌提醒（十八反十九畏），帮助师承学习者核对。

为什么这是边界案例：配伍知识有学术共识部分（禁忌表），但**临床决策的个体化极强**（体质、剂量、炮制），模型输出一旦被当作"处方依据"，责任与风险完全失控。

可行的安全形态：只做**知识检索与提示**（禁忌表的结构化查询，微调都可以不做），输出永远附"请以执业医师处方为准"；**不做剂量建议、不做处方生成、不做疗效判断**。

这个案例的价值：微调系列 85 个案例里，它教的是"**不做什么**"——边界感是行业落地的第一能力。

### CASE83. ⚪ 案例：药店用药的交互提醒（边界案例）

再选一个边界案例：药店的用药交互提醒。

场景描述：顾客买了多种药，药师要提醒相互作用（感冒药里的对乙酰氨基酚叠加剂量风险类）。

可行边界：**只做说明书层面的交互提示**（数据源是公开说明书和药典的交互表，结构化查询），输出"请咨询药师/医师"的固定引导。

不可行的边界：任何个性化用药建议（剂量调整、替代方案）——那需要完整病历和执业资格，AI 给了就是非法行医的素材。

微调在其中的角色其实很小（甚至不需要）：**这个案例放在案例集里的意义是校准预期**——很多场景的最佳方案是"检索 + 提示"，不是"训练一个模型"。

知道什么时候不训练，比会训练更专业。

### CASE84. ⚪ 案例：跨案例的复盘——成功案例的五个共性

案例二批收束前，横向复盘 85 个案例里成功项目的共性：

一、**数据现成**——历史工单/记录/判例就在库里，不用从零采集；

二、**验收客观**——对错有业务结果背书（地址改对了没、单据录对了没）；

三、**人在回路**——模型给建议，人做确认，错误有兜底；

四、**黑话浓度高**——行业术语越重，微调相对通用的优势越大；

五、**可复制**——单点验证后能横向推广（集团、连锁、同构行业）。

反面速查：数据要现采、验收靠感觉、全自动无人审、通用模型就能干——**占两条以上，重新评估要不要做**。

### CASE85. ⚪ 收束：案例集 85 篇的选择学

案例集收束，回答一个元问题：**85 个案例，你怎么挑离自己最近的那个？**

"三近"原则：**行业近**（你的行业或相邻行业，黑话和流程能直接迁移）、**数据近**（你手里已经有同类历史数据，冷启动成本低）、**风险近**（错误的代价你能兜住——建议制场景永远先于决策制场景）。

三条都近的案例，两周能出 PoC；两条近的，一个月；一条近的，先补条件再动。

最后一张地图：医疗教育金条的，先看边界案例（CASE82/83）学会不做什么；有历史单据的，从抽取类（CASE72）起步；内容行业的，从风格克隆（CASE34/76）试水。

案例的尽头是判断——**85 个案例教不完所有行业，但教得会你评估自己行业的方法**。
