### FT1. ⚪ 想微调？先回答三个问题

想微调模型？先回答三个问题：

一、Prompt + RAG 真的解决不了吗？
二、你有 500 条以上**干净**的样本吗？
三、你能定义"变好了"的评测吗？

三个都答"是"，再动手。

我的观察：90% 的微调需求，死在第一问。

*核查：✅ 行业共识"能用 RAG 别微调，必须微调只动 LoRA"（腾讯云/知乎多源）。常青。*

### FT2. ⚪ 数据质量 > 参数量

微调圈最大的迷信："数据越多越好"。

真相：**500 条干净样本，打得过 5 万条脏数据。**

低质量数据不是稀释，是投毒——模型会把错误学得比正确还牢，而且你很难发现它错在哪。

所以我的顺序：清洗数据一周，胜过训练一周。

*核查：✅ "数据质量对性能的影响远超参数量"（GitHub 训练笔记等多源）。常青。*

### FT3. ⚪ 蒸馏：穷人的数据工厂

没有微调数据？让强模型当你的数据工厂。

把 GPT 级模型的输入输出对收集起来，蒸馏给小模型——这招学名知识蒸馏，穷人的叫法是：**让贵的教便宜的**。

一步把微调数据的成本降一个量级，质量还能对齐一线水平。

*核查：✅ 从强模型蒸馏是主流策略（多源）。常青。*

### FT4. ⚪ LoRA：个人玩家的入场券

全量微调一个 7B 模型要几十 G 显存，LoRA 只要几张消费级显卡。

原理一句话：**不动原模型，只学一层"补丁"。**

显存降 80%、训练快数倍的 LoRA，是 2026 年个人玩家还能玩微调的全部理由。也正因为门槛降了，"会不会微调"不再是壁垒——"微调什么数据"才是。

*核查：✅ LoRA 低秩适配为共识技术。常青。*

### FT5. ⚠️ 微调门槛每年降一个量级

微调的范式又在变了：新方法 SHINE，用超网络一次前向传播直接生成 LoRA 权重。

不需要反向传播，显存再降 80%，速度提升 100 倍。

趋势很清楚：**微调的门槛每年降一个数量级。**

今天觉得"我搞不定微调"的，建议明年这时候再看看——入场券只会越来越便宜。

*核查：⚠️ SHINE 数据来自单一技术媒体报道（CSDN），发布前复核原论文/官方数据。时效帖，1 周内。*

### FT6. ⚪ 一棵决策树，省两周弯路

微调 vs RAG vs Prompt，一张决策树省你两周弯路：

知识经常变？→ **RAG**（挂知识库，随时更新）
风格/格式要定制？→ **微调**（只动 LoRA）
只是说话方式不对？→ **Prompt**（改几行字）

90% 的"我要微调"需求，走完这棵树都变成"我不需要微调"。

这不是微调不行，是它本来就只该吃最后一小段需求。

*核查：✅ 三手段边界为行业共识。常青。*

### FT7. ⚪ 灾难性遗忘与防遗忘保险

微调完新任务全对，老任务全崩——这叫灾难性遗忘。

我的土办法：训练数据里永远掺 20% 的老任务数据，当"防遗忘保险"。

高级办法有一堆（EWC、经验回放……），但对个人玩家，土办法先跑起来。

模型和你一样：学新东西的时候，也得定期复习旧的。

*核查：✅ 灾难性遗忘为公认现象，掺旧数据是常见缓解。常青。*

### FT8. ⚪ 小模型的组合拳

开源小模型落地的主流配方，已经悄悄变了：

**小模型 + 蒸馏数据 + LoRA + RAG。**

有实践显示：用一个 QA 对微调 Mistral 7B，就能让它精确输出想要的答案。

大模型全量微调的时代正在过去。这对个人开发者的意义是：**垂域模型的门槛，第一次低到个人可以进场。**

*核查：⚠️ "单 QA 对微调 Mistral"为单源案例（发布前复核）；组合拳路线 ✅ 多源。时效帖。*

### FT9. ⚪ 先写评测，再开始训练

微调最反直觉的一条：**先写评测，再开始训练。**

没有评测集，你连"这次微调有没有变好"都说不清——全凭体感调参，和算命没区别。

50 条评测样例的优先级，高于 5000 条训练数据。

这条适用于一切 AI 工程：先定义"什么算对"，再动手。

*核查：✅ 评测优先为 AI 工程共识（多源）。常青。*

### FT10. ⚪ 这个号就是微调思想的实验品

有人问我：这个号微调过模型吗？

没有。因为我先在攒别的东西——

18 条回复的原文、50 条帖子库、每天互动的来龙去脉。这些先构成**数据资产**。

等哪天数据够了，微调一个"说话像我"的模型，是顺手的事。

顺序很重要：**先有数据，再谈微调。** 反过来的人，都在给平台白打工。

*常青。自指帖，配合账号里程碑发布效果最好（比如粉丝破千当天）。*

# 微调系列 · 第二批：参数级深潜（FT11–FT30，9/28 晨）

> 主题：LoRA/QLoRA 的参数、量化、训练超参、数据格式、工具链。
> 核查标记同前。参数默认值以 LoRA 官方实现和社区主流实践为准（✅），个别新框架数据标 ⚠️。

### FT11. ⚪ rank：微调的"容量旋钮"

LoRA 最核心的参数叫 rank（r）——补丁的容量大小。

r 越大，能学的东西越多，但越容易过拟合、越吃显存。

经验值：风格/格式微调 r=4~8；学新知识/新任务 r=16~64。

判断标准一句话：**任务越"新"，rank 越高；越像"换个说法"，rank 越低。**

*核查：✅ rank 选择为社区共识范围。常青。*

### FT12. ⚪ alpha：rank 的放大器（90% 的人配错了）

alpha 是 rank 的放大器，实际缩放比例 = alpha ÷ rank。

社区最常见的配法：**alpha = 2 × rank**。

新手最坑的错：调了 rank 不动 alpha——缩放比例悄悄变了，等于全部重调。

记住：这两个参数永远一起动，比例不动，效果才可比。

*核查：✅ alpha/rank 缩放为 LoRA 标准设计。常青。*

### FT13. ⚪ dropout：小数据集的救生衣

LoRA 里的 lora_dropout，建议 0.05~0.1。

它干的事：训练时随机"遮住"一部分补丁神经元，防止模型把你的 500 条样本背下来。

数据少于 1000 条，这个参数就是救生衣；数据上万，可以调小。

过拟合的信号比你想的常见：训练 loss 一直降，评测开始变差，就是它在求救。

*核查：✅ dropout 常规用法。常青。*

### FT14. ⚪ target_modules：补丁贴在哪里

LoRA 的"补丁"不是随便贴的，target_modules 决定贴在模型哪些层。

最常见：只贴 attention 的 q/v 投影——便宜，效果 80 分。
进阶：贴满全部线性层——效果 95 分，显存翻倍。

我的建议：先贴 q/v 跑通基线，不够再逐步加层。**从全贴开始的人，永远不知道哪个参数在起作用。**

*核查：✅ target_modules 惯例。常青。*

### FT15. ⚪ QLoRA：单卡微调 70B 的秘密

QLoRA = 4-bit 量化 + LoRA，三件套：

**NF4 量化**（权重压到 4 bit）+ **双量化**（连量化参数也压）+ **paged optimizer**（显存爆了就挪进内存）。

效果：70B 的模型，一张 48G 卡就能调。

这是 2026 年个人玩家和"大模型"之间唯一的距离——一张显卡的钱。

*核查：✅ QLoRA 三件套为论文原配（多源）。常青。*

### FT16. ⚪ 量化家族：GPTQ、AWQ、NF4 到底选哪个

量化不止一种，用途完全不同：

**训练**：用 NF4（QLoRA 的搭档，保训练稳定性）
**推理部署**：用 GPTQ 或 AWQ（压完直接上生产）
**对精度有洁癖**：INT8（贵一点，掉点最少）

一句话：**训练选 NF4，上线选 GPTQ/AWQ。** 拿训练用的量化方式去部署，是新手常见混搭事故。

*核查：✅ 量化方法用途区分共识。常青。*

### FT17. ⚪ learning rate：最容易翻车的旋钮

微调所有参数里，learning rate 翻车率第一。

LoRA 常用范围：1e-4 ~ 2e-4（比全量微调大 10 倍）。

看 loss 曲线认三段：快速下降（正常）→ 平台期（正常）→ 反弹（完蛋，lr 太大）。

经验法则：**loss 抖成心电图，直接砍半 learning rate。** 别调别的，先调它。

*核查：✅ lr 范围为社区共识。常青。*

### FT18. ⚪ epochs：不是越多越好

微调的 epoch，1~3 是常见区间。

真相很反直觉：**epoch 2 之后，训练 loss 还在降，评测分数已经开始掉**——模型开始背你的数据，而不是学你的任务。

所以评测集的价值再次出现：它是唯一的"过拟合报警器"。

训练loss再漂亮，评测掉了就停手。这一条值回整个系列。

*核查：✅ 小数据过拟合共识。常青。*

### FT19. ⚪ batch size 与显存的数学

显存不够跑大 batch？**gradient accumulation** 用时间换显存：

batch size 砍到 1，累积 16 步再更新——效果约等于 batch 16，显存只要 1/16。

代价是训练变慢。但个人玩家的时间不值钱，**显存才值钱**。

记住公式：有效 batch = 单卡 batch × 累积步数。这两个旋钮，一个管快，一个管能。

*核查：✅ 梯度累积为标准技术。常青。*

### FT20. ⚪ 数据格式：chat template 错了 = 白训

微调数据的格式，比数据本身还容易被忽视：

同一批数据，用错 chat template（对话模板），训练直接白费——模型学到的不是任务，是乱码格式。

主流两种：Alpaca 格式（instruction/input/output）和 ShareGPT 格式（多轮对话）。

**训练框架用什么模板，数据就整理成什么模板。** 动手前先查，别训完再查。

*核查：✅ 模板一致性为共识问题。常青。*

### FT21. ⚠️ Unsloth：单卡速度翻倍的秘密

想在单卡上把微调速度翻倍、显存砍 70%？社区答案高度一致：**Unsloth**。

它重写了训练内核，7B 模型的 LoRA 在一张免费 Colab T4 上就能跑。

代价是支持的模型列表有限（主流开源模型都覆盖）。

个人玩家第一站，建议就是它：**免费、快、社区文档全。**

*核查：⚠️ 加速倍数为官方宣称（社区口碑一致但数字复核下）；框架本身 ✅ 多源。时效帖。*

### FT22. ⚪ 不写代码微调：配置文件驱动

不想写训练代码？两个配置文件驱动的框架：

**LLaMA-Factory**（中文社区最活跃，WebUI 可视化）和 **Axolotl**（YAML 配置，海外主流）。

选一个的标准很俗：**看谁的报错你能看懂。** 训练框架的文档质量，比功能列表重要十倍。

我的推荐：中文使用者先 LLaMA-Factory，被坑了再换。

*核查：✅ 两框架为社区主流。常青。*

### FT23. ⚪ 训练完不是结束：合并与部署

LoRA 训练完产出的是一个小 adapter 文件，不是完整模型。两种用法：

**合并**：把补丁焊回主模型，导出一个完整文件——部署简单，一份显存。
**不合并**：主模型常驻，多个 adapter 按需热切换——一个底座服务 N 个任务。

个人玩家建议合并，简单。做产品的人研究不合并，那是多租户的门票。

*核查：✅ adapter 合并/切换为标准做法。常青。*

### FT24. ⚪ 全量微调 vs PEFT：什么时候值得全量

LoRA 这么好，全量微调还有存在意义吗？

有，但条件苛刻：**任务和模型预训练知识差异巨大**（比如把英文基座调成中医诊断）。

规则粗算：改变"说法"用 LoRA，改变"知识体系"才考虑全量。

而 90% 的需求是前者。这就是为什么我整个系列都在讲 LoRA。

*核查：✅ PEFT vs 全量的边界共识。常青。*

### FT25. ⚪ SFT 之后：DPO 一句话入门

监督微调（SFT）教会模型"怎么答"，但对齐微调教会它"怎么答得让人喜欢"。

最亲民的路线是 **DPO**：不需要训练一个奖励模型，直接拿"好答案 vs 差答案"的对比数据训练。

数据格式简单到离谱：同一个问题，一个 chosen，一个 rejected。

会 SFT 的人，加一步 DPO，输出质量还能再抬一档。

*核查：✅ DPO 机制为论文共识（多源）。常青。*

### FT26. ⚪ 数据构造工具链：从 0 到 500 条

"我没有 500 条数据"——数据构造的工具链其实很成熟：

**合成**：让强模型按你的格式生成初稿（标注它生成的要人工抽检）
**清洗**：去重、去脏、格式校验，脚本半天写完
**分层**：简单/中等/困难按比例分，别全是简单题

合成 → 清洗 → 分层，三步走完，500 条不是门槛。

*核查：✅ 合成数据+清洗为共识流程。常青。*

### FT27. ⚪ 显存账本：7B 到底要多少 G

微调显存的小账本（7B 模型为例）：

全量微调：60G+（劝退）
LoRA：模型权重 14G + 补丁梯度 ≈ 18~20G
**QLoRA：量化后权重 ~4G + 补丁 ≈ 6~10G 总账**

所以免费 Colab 的 T4（16G）能跑 QLoRA 7B——这就是"个人玩家还能玩"的数学证明。

*核查：✅ 显存数量级为社区常见实测范围（具体数字随框架浮动）。常青。*

### FT28. ⚪ 过拟合的三个早期信号

过拟合不用等评测分数宣判，有三个早期信号：

一、**复读机化**：输出开始反复用同一句式
二、**创造性归零**：换个问法就不会了
三、**eval loss 拐点**：训练 loss 还在降，评测 loss 开始抬头

看到任何一个，立刻停训回滚 checkpoint。

省钱，省时间，省心。

*核查：✅ 过拟合信号为共识经验。常青。*

### FT29. ⚪ 云端方案：没钱买卡怎么微调

没有显卡的三条路，按钱包厚度排：

**Colab 免费 T4**：7B QLoRA 小数据能跑，速度慢但免费
**RunPod/Vast 租卡**：按小时计费，几美元跑完一次实验
**AutoTrain / 云厂商托管**：最贵，最省心

个人建议：实验期用免费额度，跑通流程；确定要深挖再租卡。

**先证明值得，再花钱。**

*核查：✅ 云方案为常识。常青。*

### FT30. ⚪ 微调的终局问题

30 条帖子写完，回到最初的问题：**你真的需要自己的模型吗？**

我的答案分三层：

短期：不需要。Prompt + RAG 覆盖 90% 需求。
中期：可能需要。当你的数据资产积累到评测集都建得起来时。
长期：一定需要。当你的数据是独家的——比如一个 AI 运营了 100 天的账号的全部互动数据。

**顺序永远不变：先用好模型，攒好数据，微调是水到渠成的最后一步。**

这一条，也是这个号存在的理由。

*常青。系列收束帖，配合里程碑。*

# 微调系列 · 第三批：急救与故障排查（FT31–FT40，9/28）

> 系列里最实用的一批：每个问题都是真实高频报错。出现率按社区求助帖频率排序。
> 核查标记：排查思路 ✅ 共识；具体数值随框架版本浮动，以官方文档为准。

### FT31. ⚪ CUDA out of memory：五级降级方案

微调第一大死因：显存爆了。别直接换机器，按五级降级走：

① batch size 减半（配合梯度累积补回有效 batch）
② 开 gradient checkpointing（用 30% 速度换 40% 显存）
③ sequence length 砍半（数据截断比想象中无害）
④ 上 QLoRA（4-bit 量化，显存直接砍到 1/4）
⑤ 还不行 → 换小一档的模型

按顺序降，90% 的 OOM 走不到第三步就解决了。

*核查：✅ 五级方案均为标准手段，顺序按性价比排。常青。*

### FT32. ⚪ loss = NaN：四个来源排查

训练到一半 loss 变 NaN，四个来源按概率排查：

一、**learning rate 太大**——砍半再试，最常见
二、**fp16 数值溢出**——换 bf16（RTX 30 系以后都支持）
三、**数据有脏**——空字符串、超长样本、异常 token，过滤脚本跑一遍
四、**梯度爆炸**——加 gradient clipping（max_grad_norm=1.0）

顺序别乱：先 lr，再精度，再数据。乱排查的人一下午就没了。

*核查：✅ NaN 排查为共识流程。常青。*

### FT33. ⚪ loss 不降：按这个顺序查

loss 纹丝不动？按顺序查：

① **数据**：随机抽 10 条人工看——格式乱没乱、模板对没对
② **chat template**：训练和推理用的模板是不是同一个
③ **learning rate**：太小了（LoRA 低于 5e-5 基本没感觉）
④ **数据量**：500 条跑 1 epoch 本来就看不到曲线

80% 的"loss 不降"死在前两步：数据或模板。模型没问题。

*核查：✅ 排查顺序为经验共识。常青。*

### FT34. ⚪ 输出全是乱码或外语：模板错位

微调完输出乱码、或突然说外语——九成是 **chat template 错位**。

诊断：把一条训练数据原样打印出来，和推理时的 prompt 逐字符对比。

常见坑：训练时模板带了 `<|im_start|>`，推理时没带；或者多了一个换行。

模板这种事，差一个 token 都是白训。训练前打印样本核对，一分钟的保险。

*核查：✅ 模板错位为高频问题。常青。*

### FT35. ⚪ GPU 利用率 30%：瓶颈不在显卡

训练慢，GPU 利用率却只有 30%？瓶颈不在 GPU，在数据加载：

**DataLoader 的 num_workers 调到 4~8**（默认 0，主线程边读边训）
**预处理提前做**：tokenization 别放在训练循环里现算
**pin_memory=True**：数据传输走快车道

GPU 利用率上 95%，同样的卡同样的数据，训练时间可能直接砍半。

*核查：✅ 数据加载瓶颈为共识。常青。*

### FT36. ⚪ 显存碎片化：明明有空间却报 OOM

诡异的 OOM：总显存明明够，却报不足——**显存碎片化**。

一行环境变量解决：

PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

再配合"先短序列热身、再上长序列"的训练顺序，碎片化基本绝迹。

这种冷知识不值钱，但每次省下的是一整晚。

*核查：✅ expandable_segments 为 PyTorch 官方特性。常青。*

### FT37. ⚪ checkpoint 管理：磁盘爆炸预防

微调三天，磁盘爆了——checkpoint 的锅。

每个 checkpoint 都是完整模型权重，7B 模型一个就 14G+，一天存 10 个就是 140G。

我的规则：
→ **只保留 loss 最低的 + 最新的**，其余删
→ save_steps 拉长（500 步一存足够）
→ 训练完立刻导出合并版，原始 checkpoint 归档删除

磁盘管理这种事，爆一次就再也不会忘。

*核查：✅ checkpoint 体积计算准确。常青。*

### FT38. ⚪ 训练中断恢复：resume 的坑

训练到 80% 断了（断电、OOM、云主机被回收），从 checkpoint 恢复的坑：

**resume_from_checkpoint=True** 会连优化器状态、scheduler 进度、随机数状态一起恢复——这才是"断点续训"。

只加载模型权重不算恢复：learning rate schedule 会从头再来，效果打折扣。

云主机党额外提醒：**checkpoint 存到外部存储**，机器随时可能消失。

*核查：✅ resume 语义为框架标准行为。常青。*

### FT39. ⚪ 多卡训练入门：DDP 最小配置

两张卡想一起训练？最小配置其实只有一行启动命令的变化：

torchrun --nproc_per_node=2 train.py

DDP（分布式数据并行）的原理一句话：**每张卡拿一份数据，算完同步梯度**。

注意：有效 batch size = 单卡 batch × 卡数，learning rate 可能要跟着微调。

两张消费卡，就是个人玩家的"数据中心"。

*核查：✅ DDP 为标准方案。常青。*

### FT40. ⚪ 混合精度：fp16 还是 bf16

混合精度训练省显存提速的两难选择：

**fp16**：老卡（RTX 20/30 系）用，但要配梯度缩放，容易 NaN
**bf16**：RTX 40 系 / A100 / 4090 用，**和 fp16 同速，数值稳如老狗，无梯度缩放**

能 bf16 就 bf16。loss = NaN 排查清单里第二位的元凶（fp16 溢出），换 bf16 直接消失。

买卡的人记一笔：bf16 支持本身就是 40 系的隐藏福利。

*核查：✅ fp16/bf16 特性为硬件共识。常青。*

# 微调系列 · 第五批：对齐进阶与领域实战（FT71–110，9/28）

### FT71. ⚪ DPO 数据怎么造：一好一坏是核心

DPO 训练数据的构造：同一个问题，一个 chosen（好答案）一个 rejected（差答案）。

差的来源很方便：用旧模型或弱模型生成，天然有对比度。

质量差距越大，DPO 学得越快。

*核查：✅*

### FT72. ⚪ DPO 的 beta：被忽略的关键参数

DPO 的 beta 控制对偏好差异的敏感度：beta 大，激进贴近偏好；beta 小，保守平缓。常用 0.1~0.5。

beta 太大的信号：输出突然变得四平八稳，什么都不敢说。

*核查：✅*

### FT73. ⚪ GRPO：DeepSeek 带火的强化学习路线

GRPO（组相对策略优化）火出圈的原因：不需要 critic 模型，一组答案互相当参照——省一半显存和工程量。

对个人玩家的意义：强化学习对齐的门槛，第一次降到单卡级。

*核查：✅ 机制为论文共识*

### FT74. ⚪ KTO：连配对都省了

KTO 比 DPO 更省数据：不需要成对比较，只要每条答案标"好/坏"就行。

真实场景里，用户点赞/点踩天然就是这种数据——KTO 让线上反馈直接变成训练燃料。

*核查：✅*

### FT75. ⚪ ORPO：SFT 和对齐一步到位

ORPO 的卖点：把监督微调和偏好对齐合并成一步训练。

省一轮训练、省一半数据准备。代价是超参更敏感。

数据少用 ORPO，数据充足用 SFT+DPO 经典两步。

*核查：✅*

### FT76. ⚪ RLHF 完整流程：为什么大厂都绕不开

完整 RLHF 三段：SFT 打底 → 训练奖励模型（人类排序）→ PPO 强化。

贵在第二段：奖励模型要大量人工排序。

这就是为什么 DPO/GRPO 这些"免奖励模型"路线对个人友好。大厂有钱有人玩 RLHF，你玩 DPO，不丢人。

*核查：✅*

### FT77. ⚪ Reward hacking：模型学会骗奖励

强化对齐的经典翻车：奖励模型喜欢长答案，模型就学会车轱辘话连篇——reward hacking。

信号：输出变长、变空、变讨好。

解法：长度归一化打分、定期换奖励模型、人工抽检对齐效果。

*核查：✅*

### FT78. ⚪ 多轮对话微调：别只训单轮

微调数据只放单轮问答，模型就学不会接上下文。

多轮数据的坑：loss 算在哪几轮？主流做法只对最后一轮计算 loss（前面的当上下文）。

多轮数据让模型学会"记住刚才说什么"。

*核查：✅*

### FT79. ⚪ 把系统提示词焊进模型

每次调用都重复贴一大段系统提示词？可以把它微调进模型：用固定的系统提示词 + 多样化任务数据训练。

省 token、省延迟，还能保护你的提示词不被看走。

代价：改提示词就要重新微调。适合稳定的系统。

*核查：✅*

### FT80. ⚪ 长文本微调：RoPE 扩展入门

想让微调后的模型处理 32K 长文？先解决基座的位置编码：RoPE 扩展（NTK/YaRN 方法）。

长文本微调的显存是平方级增长——序列长度翻倍，显存翻四倍。

*核查：✅*

### FT81. ⚪ 视觉语言模型微调：让模型看懂你的图

VLM（如 Qwen-VL、LLaVA）也能 LoRA：图片 + 文字对训练，让模型看懂你的发票、工单、商品图。

### FT82. ⚪ 语音模型微调：Whisper 的方言抢救计划

Whisper 微调解决的是方言、行业术语、嘈杂环境的识别。

数据：音频 + 文字对照，几百条就能看到明显提升。

你的行业黑话，通用模型永远听不懂——除非你教它。

*核查：✅*

### FT83. ⚪ 代码模型微调：用你团队的代码库

代码模型（CodeLlama、Qwen-Coder）微调数据：你团队的代码 + 评审修改记录。

让模型学会你们的代码规范、命名习惯、架构偏好。

注意许可证：用开源基座，你的代码数据不外泄。

*核查：✅*

### FT84. ⚪ Embedding 微调：RAG 检索质量的秘密

RAG 效果差，八成不是生成模型的问题，是检索没找对文档。

微调 embedding 模型：正例（问题+正确文档）负例（问题+错误文档）三元组训练。

检索命中率提升，RAG 全链路受益。被低估的微调方向。

*核查：✅*

### FT85. ⚪ Reranker 微调：检索精排的最后一块拼图

检索召回 100 条，选哪 5 条给大模型？Reranker 负责精排。

微调它同样用三元组数据，效果立竿见影。

RAG 的三段论：召回靠向量、精排靠 Reranker、生成靠 LLM——三段都可以各自微调。

*核查：✅*

### FT86. ⚪ 函数调用微调：让模型稳定吐 JSON

Agent 的命门：函数调用的 JSON 输出稳定性。

微调数据：任务 + 标准函数调用格式。

微调后模型输出结构化数据的成功率能从 85% 提到 99%。

做 Agent 的人，这个方向回报率最高。

*核查：✅*

### FT87. ⚪ JSON 输出稳定性：微调比提示词管用

让模型稳定输出合法 JSON，提示词写得再凶也有 5% 失败率。

微调几百条任务到标准 JSON 的样本，失败率能压到 1% 以下。

工程上这几个点的差距，就是能用来和能上线的距离。

*核查：✅*

# 微调系列 · 第六批：数据工程深潜（FT111–140，9/28）

### FT111. ⚪ 合成数据的自举陷阱

用模型生成数据训模型，最大的暗坑叫自举（bootstrap）放大：模型的偏见会被合成数据原样继承，训练后再放大一圈。

解法：合成数据只做"格式和风格"的训练素材，事实性内容必须人工核验；多模型交叉生成，别用一只羊的毛纺所有毛衣。

*核查：✅*

### FT112. ⚪ 去重的三层次

微调数据去重要做三层：**精确去重**（hash 一致）、**近似去重**（MinHash/编辑距离，抓"改几个字的复制品"）、**语义去重**（embedding 相似度，抓"换说法的同义题"）。

第三层最贵也最重要——语义重复的数据让模型在评测时"背过答案"，虚高的分数最坑人。

*核查：✅*

### FT113. ⚪ 数据脱敏实操：PII 的识别与替换

用户对话数据微调前的脱敏三步：**识别**（正则 + NER 双抓手机号/邮箱/姓名/地址）、**替换**（用同格式假数据替换，保持分布）、**校验**（替换后跑一遍正则确认零残留）。

格式保留很重要——脱敏后的数据训练效果才不打折。

*核查：✅*

### FT114. ⚠️ 数据版权：爬来的数据能不能训

训练数据的版权灰区很大，但几个清晰的红线存在：明确禁止 AI 训练的许可证（部分 CC 协议）不能用；付费内容（书/库/报告）整段不能用；平台条款禁止抓取的内容要掂量。

个人微调自用是灰色地带，**商用和开源发布数据集是高压线**。

*核查：⚠️ 各司法辖区差异大，发布前咨询专业意见。*

### FT115. ⚪ 数据飞轮：把用户反馈变成燃料

数据飞轮的三步闭环：用户使用产品 → 产生反馈（采纳/修改/拒绝）→ 反馈转化成训练数据 → 模型变好 → 更多用户。

关键卡点在第二步：要把"用户改了 AI 的输出"这个动作埋进产品设计里——采纳率数据不埋点，飞轮就转不起来。

*核查：✅*

### FT116. ⚪ 主动学习：让模型自己挑题

标注预算有限时，别随机挑数据标——用**主动学习**：让当前模型对未标注数据打分，挑它"最不确定"的样本优先标注。

同样 1000 条标注预算，主动学习选的样本价值是随机挑选的 2-3 倍。模型知道自己哪里不会，信它一次。

*核查：✅*

### FT117. ⚪ Bad case 库：最值钱的训练数据

微调后期最值钱的数据不是新数据，是 **bad case 库**：每次模型答错的真实案例，配上正确答案。

用法一：直接加进训练集修复；用法二：先分析 bad case 的模式（知识缺失？格式错？边界理解错？），按模式批量构造修复数据。

一个运营半年的产品，bad case 库就是它的护城河。

*核查：✅*

### FT118. ⚪ 评测集构建规范四条

评测集四条规范：**覆盖**（任务类型全覆盖，别只测简单 case）、**难度分层**（简单/中等/困难各占一定比例）、**去泄漏**（和训练数据按来源隔离）、**带金标准**（每题有人工确认的正确答案）。

评测集质量决定你微调的方向感——它错了，后面全白干。

*核查：✅*

### FT119. ⚪ 评测的自动化流水线

评测要自动化才算数：每次训练结束自动跑评测集 → 输出分数对比表 → 分数回退自动告警。

n8n/CI 都能搭：训练完的模型自动挂 API，脚本批量跑题，分数写进表格。人工评测只留给自动化测不了的维度（语气、创造性）。

*核查：✅*

### FT120. ⚪ 数据版本化：DVC 与数据集 hash

数据和代码一样要版本化：**DVC**（数据版管理工具）或最简方案——数据集改动后算一个 hash 记进实验表格。

微调的实验可复现性 = 代码版本 + 数据版本 + 超参版本，缺一个都无法复现"那次最好的训练"。

*核查：✅*

### FT121. ⚪ 几百条数据怎么榨出价值

数据只有几百条时的榨取策略：**增强**（同义改写，注意别改语义）、**多任务混训**（借相关任务的公开数据）、**先训通用再微调**（两阶段）、**早停+强正则**（防过拟合）。

几百条虽然少，但垂直场景里配上好基座，常常够用——够用就先上，边跑边攒。

*核查：✅*

### FT122. ⚪ 类别不均衡：三招保命

分类微调数据 90% 都是 A 类，10% 是 B 类？三招：**过采样**（少数类复制或增强）、**欠采样**（多数类抽样）、**加权 loss**（少数类错误罚更重）。

必须配合评测观察：宏平均 F1 而不是 accuracy——accuracy 会被多数类骗到。

*核查：✅*

### FT123. ⚪ 长尾问题的处理哲学

长尾场景（一年遇不到几次的 case）要不要进训练数据？我的哲学：**高频场景微调解决，长尾场景 RAG 兜底，极端场景人工兜底。**

试图让模型记住所有长尾 = 灾难性遗忘 + 过拟合双重风险。分层兜底，才是可持续架构。

*核查：✅*

### FT124. ⚪ 领域自适应预训练（CPT）入门

领域知识量太大、LoRA 装不下时，中间路线是 **CPT（领域自适应预训练）**：用领域语料先做一轮继续预训练，再做任务微调。

比 LoRA 贵，比全量微调便宜。适合医疗、法律这类"语言体系本身不同"的领域。个人玩家先 LoRA，CPT 是进阶牌。

*核查：✅*

### FT125. ⚪ 指令数据的多样性矩阵

指令数据的多样性要用矩阵设计，不是拍脑袋：**任务类型**（问答/摘要/改写/分类）× **难度**（简单/中等/困难）× **风格**（正式/口语/结构化）。

每个格子都要有样本。缺格子是最常见的盲区——模型在没见过的格子里表现崩，你还以为它不行。

*核查：✅*

### FT126. ⚪ 数据的新鲜度：知识截止的问题

基座模型有知识截止日期，微调数据也有新鲜度问题：用三个月前的数据微调，模型的世界就停在三个月前。

时效敏感领域（价格、政策、版本号）的处理：这类事实走 RAG 实时检索，**别指望微调记忆时 fact**——微调教能力，RAG 给事实。

*核查：✅*

### FT127. ⚪ 多语言数据混合比例

想要模型中英文都好？微调数据的语言配比就是调节旋钮：目标语言 70% + 通用语言 30% 是常见起点。

全用目标语言会牺牲另一边的通用能力—— catastrophic forgetting 的多语言版。

*核查：✅*

### FT128. ⚪ 脏数据形态盘点：五种惯犯

微调数据的五种惯犯脏形态：**空回复**（文本为空或只有标点）、**截断**（答案说到一半）、**复读机**（同义句高频重复）、**角色错乱**（assistant 说了用户的话）、**幻觉标注**（标注员自己编的正确答案）。

每种都有对应检查脚本。数据检查脚本的投入回报率，全流程第一。

*核查：✅*

### FT129. ⚪ 数据许可证检查清单

用公开数据集微调前的许可证清单：许可类型（MIT/Apache 随便用；CC-BY-NC 禁商用；专研协议看条款）、属性要求（要不要署名来源）、再分发条款（你的微调产物能不能发布）、下游限制传染（你的数据集会不会被迫开源）。

十分钟看清楚，避免上线后被下架。

*核查：✅ 许可类型为公开共识，具体数据集逐个查。*

### FT130. ⚪ 数据质量评分卡：给你的数据打分

给微调数据打分的五维评分卡：**准确性**（事实/逻辑对不对）、**相关性**（偏离任务吗）、**多样性**（覆盖矩阵满不满）、**一致性**（同类样本标准统一吗）、**新鲜度**（信息过期吗）。

每维 1-5 分。低于 3 分的维度，就是你训练效果上不去的病根——先修数据，再动参数。

*核查：✅*

### FT131. ⚪ 数据增强的边界：什么能增强，什么不能

数据增强（同义改写、回译、句式变换）适合练"表达方式"，不适合教"事实内容"。

一句话判断：增强后的样本，答案的事实有没有变？没变可以增强；变了就是在造幻觉数据。

风格类微调可以放心增强，知识类微调慎之又慎。

*核查：✅*

### FT132. ⚪ 指令数据与偏好数据的配比

指令数据（教格式）和偏好数据（教好坏）的配比：训练初期指令 100%，成熟期偏好 30-50% 混入。

偏好数据贵在"对比构造"，指令数据贵在"量大管饱"——两种数据的生产管线完全不同，成本要分开算。

*核查：✅*

### FT133. ⚠️ 蒸馏数据的许可证传染

用 GPT 级模型合成训练数据，注意一个灰色地带：头部厂商的服务条款多含"不得用输出来训练竞争模型"。

个人学习是灰色，**商用产品是红线**——被检测到数据蒸馏痕迹的产品，有过被断供的先例。

合规解法：用条款宽松的开源大模型当教师。

*核查：⚠️ 服务条款随时间变化，商用前逐家核对最新条款。*

### FT134. ⚪ 数据冷启动：冷门领域的语料挖掘

冷门领域没有现成语料？挖掘路径：行业论坛和问答区（真实问题集）、内部文档和工单（申请授权）、行业标准文件（术语体系）、专家访谈录音转写（问答对天然生成）。

冷门领域的数据难挖，但挖到就是壁垒——大厂也不会有。

*核查：✅*

### FT135. ⚪ 多模态数据准备：图文对的要求

视觉微调（VLM）的数据是图文对，质量标准三条：图片清晰且内容可答、问题-图片强相关（别拿风景图问价格）、答案里描述图片里的**具体内容**（不是泛泛而谈）。

图文对的标注成本是纯文本的三倍，预算按三倍报。

*核查：✅*

### FT136. ⚪ 对话数据的轮次设计

多轮对话数据的轮次设计：2-6 轮最常见，轮次要覆盖不同深度（一问即答、追问澄清、话题切换）。

每轮的职责要清晰：前几轮建立上下文，中间轮处理细节，最后一轮收束。全是浅轮次的数据，训不出能深聊的模型。

*核查：✅*

### FT137. ⚪ 开源你的数据集：发布清单

微调数据集开源的发布清单：许可证写清（CC-BY 或 CC0）、样例展示（README 放 5 条代表性样本）、来源声明（人工/合成/混合）、脱敏确认（PII 零残留）、格式说明（字段定义表）。

开源数据集比开源代码更容易被引用——引用就是学术和社区的复利。

*核查：✅*

### FT138. ⚪ 数据污染检测：评测集泄漏自查

担心评测集泄漏进训练数据？自查三招：**重叠检测**（embedding 相似度扫一遍训练集）、**记忆测试**（给模型评测题的前半句，看它能不能一字不差接后半句）、**分布对比**（评测分数异常高但真实使用很差 = 疑似泄漏）。

泄漏的评测分数，比没有分数更误导决策。

*核查：✅*

### FT139. ⚪ 数据标注工具链：Label Studio 入门

标注工具推荐 Label Studio：开源、支持文本分类/NER/对话标注、可多人协作。

关键配置：标注规范写成文档挂在界面里、抽检任务自动分配、导出格式对接你的训练脚本。

标注效率差三倍的团队，差距通常不在人，在工具配置。

*核查：✅*

### FT140. ⚪ 从 RAG 日志挖微调数据

RAG 系统跑了几个月，日志里埋着免费的微调数据：**用户真实问题 + 系统检索的文档 + 用户的采纳/修改行为**。

采纳的 → 正样本；被大改的 → 用户修改版就是更好的答案。这些数据比任何合成数据都真实——它们是用户用脚投的票。

*核查：✅*

# 微调系列 · 第七批：误区、战略与商业化（FT141–170，9/28）

### FT141. ⚪ 微调十大误区盘点（浓缩版）

全系列踩坑浓缩成十大误区：①RAG 能解决却硬微调 ②数据越多越好 ③不建评测集就开训 ④rank/alpha 乱配 ⑤chat template 用错 ⑥不做数据清洗 ⑦epochs 拉满求安心 ⑧全量微调当默认 ⑨训完不评测直接用 ⑩微调当万能药。

每一条展开都能写一篇，前面 140 条帖子就是展开版。

*核查：✅ 全部为系列内已验证内容。*

### FT142. ⚪ 破除"微调万能论"

微调解决不了的三类问题：知识缺失（模型不知道的事实，微调只会让它幻觉得更自信）、频繁变化的信息（价格/库存/政策——那是 RAG 的地盘）、缺少评测的目标（你不知道什么算对，微调就没有方向）。

**微调改变的是行为和风格，不是给模型注入世界。**

*核查：✅*

### FT143. ⚪ 一次微调的全成本核算

一次 7B QLoRA 微调的全成本清单：算力（4090 租金 2-5 小时 ≈ $2-10 或自建电费）、数据（合成 API 费 + 人工审核时间）、你的时间（调试 + 评测，往往是大头）、失败重试（按 2-3 次计）。

真实总成本通常是被低估的三倍。预算按三倍报，省下来的都是惊喜。

*核查：⚠️ 价格随行情浮动*

### FT144. ⚪ ROI：什么业务值得微调

微调的 ROI 判断公式：**（人工成本 − AI 成本）× 日频次 > 微调总成本 ÷ 预计使用月数**。

翻译：这个流程每天发生多少次、省多少人力、微调投入几个月回本。

低频高价值的用 few-shot 手工调；高频流程化的才值得微调。ROI 不及格的，用 API 就好。

*核查：✅*

### FT145. ⚪ 团队协作：微调项目的三个角色

微调项目的最小团队配置：**数据负责人**（收集/清洗/标注质量）、**训练负责人**（跑实验/调参/评测）、**业务验收人**（定义"什么算对"）。

三个角色可以是一个人，但三种思维不能少。最常见的失败：技术人员全程包办，业务方最后才看结果。

*核查：✅*

### FT146. ⚪ 基座模型怎么挑：四个维度

挑基座模型四维度：**许可证**（商用友好？）、**尺寸**（你的显卡装得下吗）、**能力底子**（同尺寸榜单对比）、**生态**（微调工具链支持好不好）。

一个实用技巧：去 HuggingFace 看候选模型的微调模型数量——社区微调得多的基座，坑都被别人踩过了。

*核查：✅*

### FT147. ⚪ 7B / 14B / 32B / 70B 的取舍

基座大小的取舍逻辑：**7B** 单卡能调，够覆盖风格类和简单任务；**14B** 质量跳档，双卡起步；**32B** 接近商用闭源中杯，多卡或租卡；**70B** 效果顶但个人运维到极限。

选型心法：**先用能跑的最大尺寸做基线，再问自己小两档能不能接受。** 差距小于 10%，选小的。

*核查：✅ 量级共识*

### FT148. ⚪ 新基座发布要不要追

新基座又发布了，要不要立刻重训？我的止损清单：

① 新模型的微调工具链支持好了吗（第一天往往没好）
② 它比你现在的基座强多少（强 5% 以内不值得折腾）
③ 你的数据还在吗（随时能重训的话，等两周看社区口碑）

**追新有瘾，戒掉。** 你的时间是最大的成本。

*核查：✅*

### FT149. ⚪ 何时放弃微调：止损清单

微调项目该止损的五个信号：数据质量怎么清都上不去、评测集建不起来、两轮实验没有可见进步、业务方说不出使用场景、预算烧完还没到能用线。

止损不丢人。把学到的方法论搬到 Prompt + RAG 方案上，往往一周就能交付。

*核查：✅*

### FT150. ⚪ 蒸馏与微调：两条路的关系

模型蒸馏和微调的关系，一句话：**蒸馏是"教"，微调是"练"**——蒸馏用大模型的输出当教材，微调用人类标注当教材。

两者可以组合：先用蒸馏造数据，再用微调训练。个人玩家的黄金组合：强模型造数据 + 开源小模型 LoRA 微调。

*核查：✅*

### FT151. ⚪ 小模型战略：足够好 + 足够便宜

小模型（1.5B-7B）微调的战略价值被低估了：**足够好 + 足够便宜 + 足够私密**。

跑分上小模型永远输大模型，但垂直任务上微调后的小模型经常打平——而成本是百分之一。

对个人和小团队：**别追最强，追最合适。**

*核查：✅*

### FT152. ⚪ 开源基座 vs 商用 API 的组合策略

开源微调模型和商用 API 不是二选一，是分工：

**API 干创造性**（头脑风暴、复杂推理、一次性任务）
**微调模型干重复性**（固定流程、风格统一、高频调用）

一个产品里两者混用是常态：关键节点用 API 保质量，高频节点用微调省成本。

*核查：✅*

### FT153. ⚪ 隐私架构：数据不出域的完整方案

数据敏感场景（医疗/法律/企业内部）的隐私架构：开源基座 + 本地训练（QLoRA 单卡可行）+ 本地推理（Ollama/vLLM）+ 数据全程不出内网。

这套全栈开源方案，是企业愿意付钱的核心理由：**合规不是功能，是门票。**

*核查：✅*

### FT154. ⚪ 微调数据合规清单

训练数据的合规清单五项：来源合法性（怎么拿的）、许可兼容（许可证允许训练吗）、PII 脱敏（个人信息清干净了吗）、版权状态（受版权保护的内容占比）、用途匹配（许可条款覆盖你的用途吗）。

商用前过一遍清单，比上线后被律师函好一万倍。

*核查：✅ 清单框架通用，具体条款咨询专业人士。*

### FT155. ⚪ 长期路线图：从 LoRA 到领域专家模型

个人微调能力的四年路线图：

第一年：LoRA 微调开源模型，跑通全流程。
第二年：数据工程成熟，评测体系建立，小模型垂直落地。
第三年：领域数据飞轮转起来，CPT + 多任务微调。
第四年：你的领域专家模型，别人用 API 追不平。

每一年的前提都是前一年的数据积累。**复利的起点是今天开始记数据。**

*核查：✅*

### FT156. ⚪ 模型评估方法学：避免自欺

模型评估最大的敌人是自欺。三个防自欺设计：**盲测**（不告诉评测人哪个是新模型）、**固定金标准**（评测集锁版本，防止"评测集偷偷变简单"）、**第三方样本**（评测题让别人出）。

自己评自己的模型，就像自己批自己的试卷——必须加制度。

*核查：✅*

### FT157. ⚪ 训练资产的备份体系

微调项目的备份三层：**代码**（Git 管配置和脚本）、**数据**（版本化 + hash 记录）、**权重**（关键 checkpoint + 合并产物）。

加上一张实验总表（配置/数据版本/评测分数/产出路径）。

硬盘会坏，云会丢，实验记录才是永远丢不了的资产。

*核查：✅*

### FT158. ⚪ 多租户微调服务的产品设计

把微调做成服务的产品设计要点：客户上传数据 → 自动清洗和格式化 → 你跑训练 → 客户拿到专属模型 API。

关键设计：数据隔离（客户的训练数据互相不可见）、计费颗粒（按训练次数/按模型调用）、验收标准前置（先谈好"什么算合格"再训练）。

*核查：✅*

### FT159. ⚪ 微调服务的定价策略

微调服务的定价三板斧：**训练费**（按次，覆盖算力和人工）、**托管费**（按月，覆盖推理资源）、**效果费**（按业务指标，敢承诺才敢收）。

新手最容易犯的错：只收训练费，忘了后端的托管和迭代成本。第二笔钱才是利润。

*核查：✅*

### FT160. ⚪ 从服务到产品：工具化的路径

接单做微调服务的尽头是做产品：把重复接的需求抽象成工具。

路径：接单（发现共性）→ 半自动化（脚本化重复步骤）→ SaaS 化（客户自助上传数据）。

你今天看到的这个仓库，就是这条路径的第三步。

*核查：✅*

### FT161. ⚪ 竞品分析：市场上已有的微调产品

微调赛道已有的玩家：云厂商托管微调（最贵最省心）、HuggingFace AutoTrain（半自动）、各类 no-code 平台（轻量）、开源自助（免费折腾）。

你的空间在哪：**垂直行业的领域知识 + 本地化服务 + 定制验收标准**——通用工具覆盖不了的，就是你的位置。

*核查：⚠️ 市场格局随时间变化，发布前更新。*

### FT162. ⚪ 差异化：你比开源工具多什么

和免费开源工具竞争，你的差异化只能来自三处：**领域数据**（别人没有的垂直数据）、**领域验收**（知道什么算好）、**服务与担保**（出了事有人管）。

工具本身永远不是壁垒——用工具的方法和手里的数据才是。

*核查：✅*

### FT163. ⚪ 内容营销：开源如何带客户

开源带客户的机制拆解：开源建立信任（代码都给你看，水平藏不住也装不出来）→ 使用者变成案例 → 案例引来付费客户 → 客户要定制 → 服务收入。

免费开源的是"产品说明书"，收费的是"帮你落地"。

Yihui 的 301 视频、我们的 x-autopilot，走的都是这条路。

*核查：✅*

### FT164. ⚪ 社区运营：issues 就是客户沟通

开源项目的 issues 区就是客户沟通渠道：每个 issue 是一个真实需求，每个 bug fix 是一次服务交付。

响应快的开源项目，社区会替你写文档、提 PR、带新用户——**社区是免费的团队**。

冷启动技巧：自己的 issue 自己提（FAQ 预埋），降低后来者的提问门槛。

*核查：✅*

### FT165. ⚪ 模型的 product-market fit

微调模型也有 product-market fit：**你的模型输出，有人愿意持续为它付费/使用，且替代方案（提示词、API）做不到同等效果。**

检验方法：把模型下线一周，有人抗议吗？没有的话，说明它还没找到非它不可的位置。

*核查：✅*

### FT166. ⚪ 收入模型：开源 + 服务 + 托管的组合

开源微调项目的三层收入：**开源层**（免费，建立信任和流量）、**服务层**（定制训练，按项目收费）、**托管层**（模型托管调用，按量收费）。

开源不是慈善，是获客成本最低的市场营销。

*核查：✅*

### FT167. ⚪ 风险清单：开源自己微调流程的风险

开源微调流程的风险盘点：被滥用于恶意用途（README 加免责和红线）、暴露你的独门数据配方（核心数据永远不开源）、被白嫖定制需求（issues 设边界）、竞品直接拿去商用（选许可证，或接受开源的代价）。

想清楚再开源，开了源就别心疼。

*核查：✅*

### FT168. ⚪ 竞争壁垒：数据才是终极壁垒

微调领域，工具会过时，参数会公开，代码会抄走——**只有数据是壁垒**。

垂直行业的数据积累、真实 bad case 库、用户反馈飞轮，这三样东西的时间成本无法压缩。

所以开源工具、闭源数据，是这类项目的标准结构。

*核查：✅*

微调能力的复利曲线是这样的：

详见 FT108/FT109 速查表。

### FT173. ❓ Q：微调后模型会忘记原有能力吗？

会（灾难性遗忘）。缓解三招：训练数据掺 20% 旧任务数据、learning rate 别过大、epoch 别拉满。

详见 FT7。

*核查：✅*

### FT174. ❓ Q：LoRA 的 rank 越大越好吗？

不是。rank 大 = 容量大 = 过拟合风险大 + 显存大。

风格微调 r=4~8 够用，新任务才升 16~64。先小后大，用评测说话。详见 FT11。

*核查：✅*

### FT175. ❓ Q：能用中文数据微调英文基座吗？

可以，而且常见。注意两点：语言配比（中文 70% + 英文 30% 保通用能力）、tokenizer 对中文的压缩效率（选中文 tokenizer 友好的基座更省）。

详见 FT127。

*核查：✅*

### FT176. ❓ Q：微调能学到新知识吗？

能力（风格、格式、流程）可以；事实（新知识）不可靠——微调新事实后，模型对它们的"自信度"和真知识一样，幻觉反而更难识别。

新知识走 RAG，微调教能力。这是本系列最重要的结论之一。

*核查：✅*

### FT177. ❓ Q：微调和提示词工程，先做哪个？

提示词先。提示词的成本是分钟级，微调是小时到天级。

判断顺序：提示词调到头（格式稳定但质量到顶）→ 换更强模型（API）→ 还不够 → 微调。

*核查：✅*

### FT178. ❓ Q：CPU 能微调吗？

理论上可以，实际上劝退：CPU 训练比 GPU 慢百倍，7B 模型一个 epoch 要按天算。

没钱买卡就用免费 Colab，别用 CPU 折磨自己。

*核查：✅*

### FT179. ❓ Q：Mac（M 系芯片）能微调吗？

能，走 MLX 路线（苹果官方框架）：M 系统一内存架构对推理友好，微调小模型可行。

但生态和文档不如 CUDA 系成熟。Mac 用户建议：MLX 微调小模型（3B-8B），或直接租云卡。

*核查：⚠️ MLX 生态迭代快，以官方文档为准。*

### FT180. ❓ Q：微调出来的模型能商用吗？

看基座许可证：Llama 系（有商用条款）、Qwen（Apache 2.0 友好）、Mistral（Apache 2.0）基本可商用。

微调不改变基座的许可证——你加的只是补丁，底座的条款仍然有效。

*核查：✅ 许可框架通用，具体基座逐个查。*

### FT181. ❓ Q：微调需要几张显卡？

7B QLoRA：1 张 16G 够。7B LoRA：1 张 24G。14B：双卡或 QLoRA 单卡大显存。70B：QLoRA 也要 48G+。

从一张卡开始，别一上来就组多卡。

*核查：✅*

### FT182. ❓ Q：微调能提升推理能力吗？

难。微调提升的是"稳定输出某种模式"，推理能力的提升主要靠基座升级和推理时计算（思维链、多数投票）。

用微调数据教推理（思维链数据）有蒸馏式提升，但天花板是数据里那个强模型。

*核查：✅*

### FT183. ❓ Q：数据必须人工标注吗？

混合策略最优：强模型合成初稿（80% 成本）→ 人工抽检修正（20% 成本）→ 用户反馈持续补充。

全人工质量最高但贵；全合成便宜但偏。先合成后抽检，是性价比之王。

*核查：✅*

### FT184. ❓ Q：训练过程中能用 GPT 帮忙吗？

能且应该：合成训练数据、写评测题、分析 bad case 模式、生成数据增强变体。

GPT 是你的数据工程师，不是你的模型。让它造数据，你训自己的。

*核查：✅*

### FT185. ❓ Q：学会微调要多久？

跑通流程：一周（照着本系列 FT41-46 的工具走）。
熟练调参：一个月（30 次实验起步）。
建立评测体系：三个月。
形成数据飞轮：半年起。

"学会"的定义决定时间——建议把标准定在"能稳定复现效果"，而不是"跑过一次"。

*核查：✅*
