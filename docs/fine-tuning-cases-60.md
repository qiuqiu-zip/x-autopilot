# 微调案例集（技术实施拆解） · 草稿（CASE1–CASE40，9/28，未发布）

> 定位：40 个微调项目的**技术实施全程拆解**（基座/数据/配置/坑/结果/成本）。
> 与行业案例集（商业视角）区分：本系列是工程视角的实操复盘。
> 案例为基于常见场景的示例拆解（参数与结果为典型值），实施前用自己的数据验证。

## 对话与客服类（CASE1–8）

### CASE1. ⚪ 案例：7B 客服话术微调全程

**任务**：电商售后客服的话术标准化。**基座**：Qwen 7B。**数据**：脱敏客服对话 1,200 条（用户问 + 标准回复对）。**配置**：QLoRA（r=16, alpha=32, lr=1e-4, 2 epochs）。**坑**：初版把多轮对话拍平成单轮，模型学不会接上下文——改成只对最后一轮算 loss 后解决。**结果**：话术风格一致性人工评分 3.2→4.5（5 分制）。**成本**：4090 租用 3 小时 ≈ $2。**复盘**：数据模板一致性比数据量重要。

### CASE2. ⚪ 案例：多轮客服的轮次设计

**任务**：客服多轮对话（处理追向和澄清）。**基座**：Qwen 14B。**数据**：2-5 轮对话 800 段。**配置**：QLoRA（r=32，多任务较复杂），只对 assistant 最后一轮算 loss。**坑**：上下文里塞了 10 轮历史，显存爆炸——历史摘要化后解决。**结果**：多轮任务完成率 61%→84%。**成本**：单卡 6 小时。**复盘**：多轮微调的数据构造成本是单轮的三倍，预算要提前翻倍。

### CASE3. ⚪ 案例：情绪识别的客服质检

**任务**：客服对话的情绪与合规质检（分类任务）。**基座**：Qwen 3B（分类任务小模型够）。**数据**：标注对话 3,000 条（合规/情绪/流程三类标签）。**配置**：LoRA 全层（r=8），3 epochs。**坑**：类别不均衡（合规违规只占 4%）——加权 loss + 过采样后宏 F1 从 0.71 到 0.86。**结果**：全量质检替代 5% 抽检。**成本**：本地 4090 半天。

### CASE4. ⚪ 案例：智能外呼的话术微调

**任务**：外呼机器人的话术自然化（机器人腔→人味）。**基座**：Qwen 7B + 语音合成。**数据**：真人销售录音转写 600 段。**坑**：文本微调后语音合成的停顿不自然——在文本里显式加入停顿标记后解决。**结果**：外呼完播率 23%→41%。**复盘**：文本微调和语音合成是两个模型——联调的坑比各自的多。

### CASE5. ⚪ 案例：工单分类与路由

**任务**：工单自动分类路由（12 类）。**基座**：3B 小模型。**数据**：历史工单 5,000 条。**配置**：LoRA（r=8），分类头微调。**坑**：长尾类别（每类不足 50 条）效果差——合并小类为"其他"+人工兜底。**结果**：top1 准确率 89%，路由人工工作量减 70%。**复盘**：分类任务的类目设计比模型选择重要——类目互斥才能分得准。

### CASE6. ⚪ 案例：客服知识库的联合优化

**任务**：RAG + 微调组合（客服场景）。**架构**：RAG 检索产品文档 + 微调模型统一口径输出。**数据**：微调数据 800 条（标准口径问答）。**坑**：RAG 检索的内容和微调口径冲突（模型更信微调的风格，篡改了检索的事实）——提示词里明确"事实以检索内容为准，风格按训练"后解决。**结果**：口径一致 + 事实准确双达标。**复盘**：RAG+微调的组合，冲突测试必须做。

### CASE7. ⚪ 案例：售前咨询的销售话术

**任务**：售前咨询的销售话术（不越界版）。**基座**：Qwen 14B。**数据**：合规话术 500 条 + 违规话术 300 条（对比训练）。**配置**：SFT + DPO 两阶段（DPO 数据：合规回复 vs 过度承诺回复对）。**结果**：违规承诺率 7%→0.3%。**复盘**：合规场景用 DPO 比纯 SFT 好——SFT 教"该说什么"，DPO 教"不该说什么"。

### CASE8. ⚪ 案例：跨语言客服的混合微调

**任务**：中英双语客服。**基座**：Qwen 14B。**数据**：中文 2,000 + 英文 800（配比 7:3 保通用能力）。**坑**：全中文数据训练后英文能力崩了（灾难性遗忘的双语版）——加英文通用数据混训后恢复。**结果**：双语客服上线。**复盘**：多语言微调的语言配比，是保住基座能力的旋钮。

## 文档与文本类（CASE9–16）

### CASE9. ⚪ 案例：合同风险条款识别

**任务**：合同风险条款标注。**基座**：Qwen 14B。**数据**：合同 + 法务标注 900 份。**配置**：LoRA（r=32，长文本任务）。**坑**：长合同（50 页+）超上下文——按条款切分逐段审查 + 汇总。**结果**：风险条款召回 92%（法务双人标注为基准）。**成本**：租 A100 2 小时 ≈ $8。**复盘**：长文档任务先设计切分，再设计训练。

### CASE10. ⚪ 案例：判决书要素提取

**任务**：判决书结构化提取（当事人/法条/判决结果）。**基座**：Qwen 7B。**数据**：判决书 2,000 份 + 结构化标注。**配置**：LoRA + JSON 输出微调。**坑**：判决书格式各地法院不统一——按法院分组增强数据后鲁棒性提升。**结果**：要素抽取 F1 0.91。**复盘**：格式多样的领域，数据覆盖的"格式多样性"比"数量"重要。

### CASE11. ⚪ 案例：会议纪要的自动化

**任务**：会议录音转写 → 结构化纪要（决议/待办/责任人）。**架构**：Whisper 转写 + 微调模型结构化。**数据**：转写文本 + 纪要对 400 份。**坑**：口语的冗余和跑题——训练数据里保留"口语原文"，模型学会从乱糟糟的口语里提取结构。**结果**：纪要初稿可用率 85%。**复盘**：口语到结构化的微调，数据里的"脏"不能洗——模型要学的是从脏到净。

### CASE12. ⚪ 案例：技术文档的问答对构建

**任务**：技术文档问答（内部 RAG 的微调层）。**数据**：文档切片 + 生成 QA 对 1,500 条（强模型生成 + 人工抽检 20%）。**配置**：LoRA。**坑**：合成 QA 对里 15% 的问题在文档中无答案——增加"无法回答"类样本，模型学会说"文档中未提及"。**结果**：幻觉率 31%→9%。**复盘**：**"拒答能力"也是可以微调出来的。**

### CASE13. ⚪ 案例：周报生成的翻译官

**任务**：git commit + 项目数据 → 周报。**基座**：Qwen 7B。**数据**：commit 历史 + 历史周报对 300 份。**配置**：LoRA（r=8）。**坑**：个人文风差异大——按人生成、按人存储，每个人的周报用自己微调的版本。**结果**：周报撰写时间 40 分钟→5 分钟。**复盘**：个人风格任务，"一人一模型"比"一模型服务所有人"效果好。

### CASE14. ⚪ 案例：简历初筛的合规版

**任务**：简历技能匹配（合规版：只评技能不评人）。**基座**：3B。**数据**：JD + 简历 + 匹配度标注 2,000。**配置**：分类微调。**合规设计**：删除性别/年龄/院校字段（只保留技能与经验描述）+ 输出不带人名（输出匹配度不输出排名）。**结果**：初筛时间 70%。**复盘**：合规不是事后过滤，是训练数据设计时就删掉敏感字段。

### CASE15. ⚪ 案例：法律翻译的术语强约束

**任务**：合同中英翻译（术语强一致）。**基座**：Qwen 14B。**数据**：双语合同 800 份 + 术语表 500 条（作为约束注入提示词）。**配置**：LoRA。**坑**：同一术语不同译法混训——术语表统一后一致性从 78% 到 97%。**结果**：翻译初稿 + 人工终审成为流程。**复盘**：术语一致性靠"数据一致性"，不靠模型自觉。

### CASE16. ⚪ 案例：企业知识库的口径统一

**任务**：企业内部问答的口径统一（不同部门对同一政策的说法不一）。**架构**：RAG（检索政策原文）+ 微调（统一表述口径）。**数据**：标准口径问答 600 条。**坑**：政策更新后旧口径数据要下架——数据集版本化管理后解决。**结果**：跨部门口径一致率 95%。**复盘**：口径类微调的数据有"保鲜期"，版本管理是运维的一部分。

## 代码与数据类（CASE17–24）

### CASE17. ⚪ 案例：代码评审助手

**任务**：代码评审助手（学会团队的评审标准）。**基座**：Qwen-Coder 14B。**数据**：历史 PR 的 diff + review 评论 1,500 对。**配置**：LoRA。**坑**：评审意见里"为什么"的缺失——数据清理时保留评审理由（不只保留改了什么）。**结果**：评审意见采纳率 68%。**复盘**：评审微调的数据质量，取决于历史 review 里是否保留了理由。

### CASE18. ⚪ 案例：SQL 生成助手

**任务**：自然语言转 SQL（内部数仓）。**基座**：Qwen-Coder 14B。**数据**：问题 + 正确 SQL + 表结构 1,200 对。**配置**：LoRA + 表结构注入提示词。**坑**：字段名是拼音缩写（内部黑话）——表结构文档微调进模型后准确率提升。**结果**：SQL 可执行率 74%→93%。**复盘**：内部黑话（字段名/表名）必须成为训练数据的一部分。

### CASE19. ⚪ 案例：测试用例生成

**任务**：单元测试用例生成。**基座**：Qwen-Coder 7B。**数据**：函数 + 测试用例对 2,000。**配置**：LoRA。**坑**：生成的测试有"永真"测试（断言恒真不算覆盖）——测试有效性校验（故意引入 bug 看测试能不能抓到）加入评测。**结果**：测试覆盖率 55%→81%，且有效性验证通过。**复盘**：代码生成的评测，"能跑"不够，要"有效"。

### CASE20. ⚪ 案例：日志分析的异常检测

**任务**：日志异常模式识别（运维）。**基座**：3B。**数据**：历史日志 + 异常标注 8,000 条。**配置**：分类微调。**坑**：日志格式五花八门——按服务分组训练（每个服务一个模式）。**结果**：异常检出率 82%，误报率 11%。**复盘**：日志微调的前提是日志规范化——脏日志先治理再微调。

### CASE21. ⚪ 案例：API 文档问答

**任务**：内部 API 文档问答（RAG + 微调）。**数据**：API 文档 + 历史开发者问答 900 条。**坑**：API 版本迭代快——文档版本戳 + 微调数据同步更新机制。**结果**：开发者问题自助解决率 64%。**复盘**：API 文档问答的运维成本主要在"版本同步"，不在训练。

### CASE22. ⚪ 案例：数据报表的口径统一

**任务**：报表口径的问答统一（"GMV 怎么算的"每次答案一致）。**数据**：指标定义文档 + 历史问答 500 条。**配置**：RAG + LoRA 双层。**结果**：口径问题的一致性回答率 99%。**复盘**：口径统一类任务，RAG（检索定义）+ 微调（统一表述）缺一不可。

### CASE23. ⚪ 案例：代码迁移助手（语言 A→B）

**任务**：旧语言到新语言的代码迁移。**基座**：Qwen-Coder 14B。**数据**：迁移对 800 对（旧代码 + 新代码）。**配置**：LoRA。**坑**：迁移不只翻译语法，还有惯用法（新语言的 best practice）——数据里包含迁移后的重构版本而非直译版。**结果**：迁移初稿采纳率 61%。**复盘**：代码迁移微调的数据，要用"迁移后的正确姿势"，不是"逐行翻译"。

### CASE24. ⚪ 案例：数据清洗脚本的自动化

**任务**：为不同格式的数据生成清洗脚本。**基座**：Qwen-Coder 7B。**数据**：脏数据样本 + 清洗脚本对 500 对。**结果**：数据清洗的脚本编写时间减 60%。**复盘**：元任务（生成工具的 AI）的微调，训练数据来自"过去手动干的活"——**你工作的历史，就是微调的数据集。**

## 专业领域类（CASE25–32）

### CASE25. ⚪ 案例：医疗分诊的合规落地全程

**任务**：分诊引导（合规版）。**基座**：Qwen 14B。**数据**：分诊对话 1,500（脱敏）。**合规三件套**：训练数据删诊断结论（只留科室推荐）、输出模板带免责声明、紧急症状关键词强制急诊路由。**坑**：模型偶尔"热心"给用药建议——DPO 负样本（用药建议类回复）压制。**结果**：科室推荐准确率 88%，零诊断输出。**复盘**：医疗微调的合规成本 ≈ 技术成本——但合规就是入场券。

### CASE26. ⚪ 案例：医保政策问答

**任务**：医保政策问答（本地 RAG + 微调）。**数据**：政策文档 + 问答对 700。**坑**：政策的地域差异（各市规则不同）——按地区路由 + 分地区数据。**结果**：政策问答准确率 91%。**复盘**：政策类问答的"地域路由"是被忽略的架构设计。

### CASE27. ⚪ 案例：医学文献的科普转译

**任务**：医学论文 → 患者科普。**基座**：Qwen 14B。**数据**：论文 + 科普版对 400。**配置**：LoRA。**坑**：科普的"度"（通俗但不失准确、不产生误解）——医学顾问参与的评测集把关。**结果**：科普审核通过率 82%。**复盘**：科普转译的评测必须领域专家参与——通用评测测不出"医学上误导"。

### CASE28. ⚪ 案例：保险条款问答

**任务**：保险条款的人话翻译。**基座**：Qwen 14B。**数据**：条款 + 人话解释对 600。**合规**：解释 ≠ 承诺（输出模板规避赔付承诺）。**结果**：条款类咨询自助解决率 71%。**复盘**：金融保险类微调的输出，全部走合规模板套壳。

### CASE29. ⚪ 案例：财报问答的口径引擎

**任务**：财报数据问答。**架构**：Text-to-SQL + 微调口径解释。**数据**：财报问题 + SQL + 口径说明 800。**结果**：数据类问题自动应答 76%。**复盘**：金融数据问答 = 取数（SQL）+ 解读（口径）两层，微调主要优化解读层。

### CASE30. ⚪ 案例：投教内容的分层生成

**任务**：投资者教育内容（按知识水平分层）。**基座**：Qwen 7B。**数据**：同主题三层深度内容对 400。**合规**：教育内容不涉及标的推荐（模板规避）。**结果**：内容产能 ×6，合规零事故。**复盘**：合规敏感行业的内容微调，模板规避 + 数据洁癖是两条命。

### CASE31. ⚪ 案例：反欺诈话术的识别

**任务**：诈骗话术识别（客服对话里的风险信号）。**基座**：3B。**数据**：标注对话 4,000。**结果**：欺诈识别 F1 0.89。**复盘**：反欺诈的文本微调，数据里必须有**最新的诈骗剧本**——骗术在进化，数据要月更。

### CASE32. ⚪ 案例：制裁名单的合规筛查

**任务**：交易对手的制裁名单筛查（合规）。**基座**：3B + 规则引擎混合。**数据**：名单匹配样本 + 模糊匹配标注 2,000（制裁名单的翻译变体/缩写）。**结果**：模糊匹配召回 96%。**复盘**：制裁筛查的难点不是分类，是**变体识别**（同一个实体的一百种写法）。

## 生活方式与创意类（CASE33–40）

### CASE33. ⚪ 案例：个人助理的隐私微调

**任务**：个人助理（日程/邮件/笔记整理）。**基座**：Qwen 7B 本地。**数据**：个人数据（邮件草稿对 300、日程处理样本 200）。**架构**：本地 QLoRA + Ollama 部署——**数据全程不出本机**。**结果**：个人邮件草稿采纳率 70%。**复盘**：个人数据的微调，本地化部署是隐私的唯一解。

### CASE34. ⚪ 案例：写作风格的克隆实验

**任务**：写作风格克隆（用自己 100 篇文章微调）。**基座**：Qwen 14B。**数据**：文章 100 篇。**配置**：LoRA（r=16）。**结果**：盲测中 60% 的段落被认出是"我的风格"（vs 20% 基线）。**诚实结论**：风格学到了七成，观点和经历学不到——克隆体适合放大产量，不适合替代本人。

### CASE35. ⚪ 案例：翻译风格的驯化

**任务**：翻译风格驯化（消除翻译腔）。**数据**：双语对照 + 精修版 500。**结果**："翻译腔"盲测识别率下降 45%。**复盘**：翻译微调的本质是"教模型目标语言的母语者习惯"——精修版和机翻版的对比数据是关键。

### CASE36. ⚪ 案例：播客的 AI 制作管线

**任务**：播客制作管线（非微调，但相关）。**架构**：选题（LLM）→ 大纲 → 录音 → Whisper 转写 → AI 剪辑点标记 → shownotes 生成。**结果**：单集制作 8h→3h。**复盘**：管线里 AI 干"准备和整理"，人干"录制和观点"——分工清了，产能就来了。

### CASE37. ⚪ 案例：短视频脚本的爆款结构学习

### CASE38. ⚪ 案例：儿童教育的分寸实验
