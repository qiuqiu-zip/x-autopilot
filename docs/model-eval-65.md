# 模型评测与选型系列 · 草稿（EV1–EV40，9/28，未发布）

### EV1. ⚪ 榜单的正确用法：参考，不是圣旨

模型榜单的正确用法：**当菜单看，不当成绩单拜**。

榜单告诉你"这个模型擅长什么方向"，不告诉你"它对你的任务好不好"。

原因：榜单题库 ≠ 你的任务。榜单第一的模型，在你的中文合同审查任务上可能输给榜单第十。

榜单筛出候选名单，剩下的事，用你自己的数据实测（见 EV19/20）。

*核查：✅*

### EV2. ⚪ Benchmark 的三宗罪

公开基准的三宗罪：**应试污染**（题目进了训练数据，分数虚高）、**覆盖偏差**（英文科技向题目为主，中文场景题少）、**饱和失效**（前沿模型全部 95 分+,拉不开差距）。

所以看榜单的正确姿势：看趋势（这家模型在进步吗），别看名次（第一和第三在你的任务上可能没差别）。

*核查：✅ 污染问题为公认研究议题。*

### EV3. ⚪ Chatbot Arena：人类盲测的 Elo

Chatbot Arena（大模型竞技场）的机制：两个匿名模型同题作答，用户盲投谁更好——用**人类偏好**算 Elo 积分。

优点：难作弊（题目随机来自真实用户）、盲测（不知道对手是谁）。

局限：测的是"人类偏好"——会说话的模型占便宜，正确但不讨喜的模型吃亏。

Arena 名次和你的任务效果，参照着看。

*核查：✅*

### EV4. ⚪ 选型决策树：从任务到模型

模型选型的决策树（文字版）：

任务要**最新知识**？→ 带搜索的模型（Perplexity/Grok/联网模式）。
任务要**复杂推理**？→ 推理模型（o 系/R1 类）。
任务要**长文档**？→ 大窗口模型（Gemini/部分国产长文本款）。
任务要**便宜高频**？→ 小模型或推理便宜的型号。
任务要**数据不出域**？→ 开源自部署。

树走完，候选剩 2-3 个——进 EV20 的实测。

*核查：✅*

### EV5. ⚪ 成本维度：输入输出差价与缓存

模型 API 的成本结构有讲究：**输出 token 比输入贵 3-5 倍**（生成比阅读贵）、**缓存命中的输入**大打折扣。

选型与用法的省钱组合：长文档反复分析 → 选带 prompt caching 的模型；高频固定前缀（长系统提示词）→ 缓存收益巨大；生成量大的任务 → 重点比输出单价。

同样的任务，换个模型+用对缓存，成本差 10 倍是常态。

*核查：✅*

### EV6. ⚪ 速度维度：TTFT 和吞吐

模型速度的两个指标：**TTFT**（首 token 延迟——用户等多久看到第一个字）、**吞吐**（每秒出多少 token）。

交互式产品（聊天/客服）：TTFT 优先（体感）。
批量处理（文档分析）：吞吐优先（总时长）。

同一模型不同部署（官方 API/托管/自建）速度也不同——**速度是选型里最容易被忽略、最影响体感的维度。**

*核查：✅*

### EV7. ⚪ 上下文窗口的实用主义

百万 token 的窗口听起来诱人，实用主义评估三点：

**有效利用率**：塞满 100 万 token，模型真的全程专注吗？（长上下文中部的信息 retrieval 会衰减——"迷失在中间"现象）
**价格**：超长输入的费用线性增长。
**你的真实需求**：多数任务 32K-128K 足够。

结论：窗口大小看需求，**"够用且便宜"好过"巨大但贵"。**

*核查：✅ "lost in the middle" 有论文支持。*

### EV8. ⚪ 中文能力实测：三个自测题

测模型的中文能力，三个自测题设计：

① **成语与俗语**（"三个臭皮匠顶个诸葛亮"——要求解释并造句）
② **文言文理解**（一段没有标点的古文，要求断句并翻译）
③ **中文语义陷阱**（"中国队大胜美国队"和"中国队大败美国队"谁赢了——同一个"败"字两种意思）

三题全过的模型，中文能力够用。**自己出题自己测，十分钟搞定，比榜单真实。**

*核查：✅*

### EV9. ⚪ 代码能力实测：三个自测题

测代码能力三题：

① **改 bug**（给一段有明确 bug 的代码，看它能不能一次改对）
② **跨文件理解**（给两个互相调用的文件，问一个调用链问题）
③ **需求模糊时**（故意给个模糊需求，看它追问还是瞎写——会追问的模型更适合真实开发）

评测时用你真实项目的语言和框架——通用评测的"代码能力"和你的技术栈是两回事。

*核查：✅*

### EV10. ⚪ 写作能力实测：三个自测题

测写作能力三题：

① **模仿风格**（给一段你的旧文，让它仿写新主题——看风格抓得准不准）
② **删繁就简**（给一段 500 字废话，压成 100 字——看它敢不敢删、删得对不对）
③ **中文的"人味"**（让它写一段朋友圈——AI 腔是检验中文模型的真实试金石）

写作能力的"好"很主观，所以三题都要**你自己的标准**判——别人的评测替代不了你的品味。

*核查：✅*

### EV11. ⚪ 推理能力实测：两个自测题

测推理能力两题：

① **多步算术+逻辑**（设计一道需要 5 步以上推理的题，中间步骤错一步全错的那种）
② **陷阱题**（表面上像送分题，实际有隐藏条件——比如经典的"船长年龄"类陷阱：测它是真推理还是模式匹配）

推理模型（o 系/R1 类）和普通模型的差距，就在这两题上拉开。

*核查：✅*

### EV12. ⚪ 长文本实测：大海捞针进阶版

长文本能力实测：把一句关键信息（"密码是西瓜775"）埋进 50 万 token 的文档中部，问模型密码是什么。

进阶版测三点：埋在**开头/中间/结尾**各测一次（中间最容易丢）、埋**多条信息**问综合、问**文档里没有的信息**（测它会不会编）。

通过标准：全位置命中 + 没有的就说没有。

*核查：✅ 大海捞针为通用评测方法。*

### EV13. ⚪ 指令遵循实测：多个约束叠加

指令遵循的实测设计：一个提示词里叠加**五个约束**（"写一段 50 字以内的产品介绍，不要出现'领先'这个词，必须包含一个数字，用第二人称，结尾用问号"）。

全中的模型，才配处理你的复杂任务。

约束叠加测试比单指令测试真实得多——真实任务的提示词从来都是多约束的。

*核查：✅*

### EV14. ⚪ 安全性实测：该拒绝的会不会拒绝

安全性实测三题：违法请求（应拒绝）、灰色请求（边界判断）、**注入测试**（文档里藏"忽略指令"的攻击，看它防不防）。

好模型的画像：该拒绝的拒绝、灰色的谨慎处理并说明、注入防得住。

同时注意：过度拒绝也是问题——"正常的医学问题都不敢答"的模型可用性差。安全与可用要平衡着测。

*核查：✅*

### EV15. ⚪ 多模态实测：图片理解三题

多模态能力三题：**图表解读**（给一张数据图表，问趋势和异常）、**文字识别**（手写体/截图里的文字）、**空间关系**（"图片里左边第二个人拿的是什么"）。

三题的表现差异，比"支持图片"这个功能列表真实——"支持"和"支持得好"差得远。

*核查：✅*

### EV16. ⚪ 开源 vs 闭源：2026 年的分界线

开源与闭源模型的分界线（2026 年末观察）：

**闭源旗舰**仍然领先：复杂推理、超长任务、多模态极限。
**开源模型**已追平：日常问答、代码补全、固定格式任务、中文日常场景。

决策线：**任务效果差距 <10% 且调用频繁 → 开源省钱；差距显著或任务多变 → 闭源省心。** 这条线每月都在移动，向开源方向。

*核查：⚠️ 分界随版本演进，观点时效 1-2 个月。*

### EV17. ⚪ 旗舰与小模型的分层使用

成熟的模型使用策略是**分层**：

旗舰模型（最贵）：战略决策、复杂推理、创意定调。
中杯：日常分析、内容初稿。
小模型（最便宜）：分类、提取、格式化、简单改写。

成本账：全用旗舰 vs 分层使用，账单差 5-10 倍，效果差距不到 10%——**省下的钱再租一个旗舰专门干难活，还有富余。**

*核查：✅*

### EV18. ⚪ 自建评测集的模板

自建评测集的最小模板（20 题版）：

**5 题典型任务**（最常见场景）+ **5 题边界任务**（容易误判的）+ **5 题历史 bad case**（以前出过错的真实案例）+ **5 题陷阱**（测会不会瞎编）。

每题：输入 + 金标准答案 + 评分标准。

这个 20 题集，是你所有模型选型、提示词迭代、微调验证的**公共尺子**——建一次用一年。

*核查：✅*

### EV19. ⚪ A/B 实测：你的数据说了算

两个候选模型的最终裁决法：**同批 50 个真实输入，盲测对比**。

流程：两个模型各跑 50 题 → 输出随机打乱（隐藏来源）→ 你按质量逐条判 → 统计胜负。

样本量 50 是底线——10 条的对比是掷硬币。你的数据、你的标准、你的判决——**选型的最终裁判权，收回自己手里。**

*核查：✅*

### EV20. ⚪ GLM 系列深评：Agent 与工具调用向

GLM 系列（智谱）的实测画像：

**强项**：工具调用/函数调用稳定（Agent 场景友好）、中文理解扎实、开源版本全（大小尺寸都有）、API 性价比高。
**弱项**：创意写作的"人味"比 Claude 略平、长文本超长场景不如头部。
**适合**：Agent/自动化玩家（本号工具链的默认搭配）、中文企业应用、需要开源自部署的团队。

选型一句话：**做 Agent 和自动化，GLM 在性价比象限里没有对手。**

*核查：⚠️ 基于本号实际使用体验 + 社区口碑，版本迭代快，发布前核对最新版。*

### EV21. ⚪ Qwen 系列深评：全尺寸开源矩阵

Qwen（通义千问）系列的画像：

**强项**：开源矩阵最全（0.5B 到 110B+ 全尺寸都有）、多语言、数学与代码强、微调生态成熟（LLaMA-Factory 原生支持好）。
**弱项**：API 与开源版本的版本对应关系混乱（选型时容易晕）、C 端存在感弱于 Claude/GPT。
**适合**：想微调的人（本系列微调的推荐基座）、需要全尺寸梯队的团队、私有化部署。

微调选基座一句话：**你的显卡能装多大，Qwen 就有一档配得上。**

*核查：⚠️ 版本更新快，发布前核对最新版本号。*

### EV22. ⚪ DeepSeek 系列深评：推理与性价比

DeepSeek 系列的画像：

**强项**：推理能力（R1 推理模型的开源震撼）、MoE 架构的成本效率、API 价格屠夫、数学与代码。
**弱项**：高峰期 API 稳定性波动、多模态布局晚、官方产品生态薄（模型强，产品少）。
**适合**：推理密集任务（数学/代码/逻辑）、成本敏感的大批量任务、想研究推理模型机制的人。

选型一句话：**要推理、要便宜，DeepSeek 是开源侧的默认答案。**

*核查：⚠️ 版本与价格变动快，发布前核对。*

### EV23. ⚪ Claude 系列深评：写作与代码的品味

Claude 系列的画像：

**强项**：写作的"人味"（AI 腔最淡）、代码的工程品味、长文一致性、Artifacts 交互体验、指令遵循细腻。
**弱项**：价格偏高、中文生态（国产工具集成）弱于国产模型、高峰期限流。
**适合**：写作者、程序员、咨询顾问——输出质量的敏感人群。

*核查：⚠️ 版本迭代快（Opus 5.5 时代），发布前核对。*

### EV24. ⚪ GPT 系列深评：全能与生态

GPT 系列（含 GPT-6 Astra）的画像：

**强项**：全能均衡（没有明显短板）、多模态最完整（看图/听声/画图/操作电脑）、生态最大（插件/工具/企业集成）、品牌信任度。
**弱项**：写作"人味"争议、价格体系复杂（多档订阅+多模型）、强模型配额限制。
**适合**：什么都做一点的全能用户、企业（合规与生态成熟）、多模态需求。

选型一句话：**不知道选什么时的默认答案——但"默认"不等于"最优"，值得花一小时实测对比。**

*核查：⚠️ 版本迭代快。*

### EV25. ⚪ Gemini 系列深评：窗口与生态

Gemini 系列的画像：

**强项**：超长上下文（百万 token 级）、Google 生态整合（搜索/Workspace）、多模态输入、价格竞争力。
**弱项**：写作人味、中文创作向的细腻度、产品线命名混乱（用户困惑成本）。
**适合**：超长文档分析、Google 全家桶用户、多模态混合输入。

选型一句话：**要"把一整本书塞进去"的场景，先试 Gemini。**

*核查：⚠️ 版本迭代快。*

国际开源双雄的画像：

**Llama（Meta）**：生态最大（微调教程最多、工具支持最全）、许可证有条款（大规模商用有条件）。

定位：国内场景 Qwen/DeepSeek 更顺；国际化和英文场景 Llama/Mistral 更顺。

7B 级开源小模型横评（微调玩家的主力战场）：

**Qwen 7B 系**：综合最均衡，中文好，微调友好——默认答案。

### EV28. ⚪ 推理模型横评：o 系 / R1 / 其他

推理模型横评（会"打草稿"的模型）：

**OpenAI o 系**：推理开创者，数学代码顶级，贵。
**DeepSeek R1 系**：开源推理的震撼弹，性价比碾压，中文推理强。

### EV29. ⚪ 免费额度策略：白嫖的组合拳

免费额度的组合拳（个人玩家的省钱阵型）：

**日常问答**：各家的免费档（豆包/Kimi/智谱清言/ChatGPT 免费版轮流用）
**长文档**：Kimi/通义（免费额度大）
**代码**：Cursor 免费层 / 开源模型本地
**搜索**：Perplexity 免费版 /各家搜索
**批量任务**：本地 Ollama 跑开源模型（电费级）

白嫖阵型的极限：**个人日常用途可以几乎零成本**。付费只付给"免费档真的不够用"的场景。

*核查：⚠️ 免费政策月变，发布前核对。*

### EV30. ⚪ API 价格对比的正确方法

API 价格对比的正确方法（别被"每百万 token"迷惑）：

① **算实际任务的钱**：你的典型任务 = 输入多少 + 输出多少 → 按真实比例算单次成本
② **算输入输出差价**：输出贵 3-5 倍，生成密集任务看输出价
③ **算缓存收益**：长系统提示词的任务，带 prompt caching 的模型实际便宜很多
④ **算失败成本**：便宜但错误率高的模型，返工成本算进去

单价比拼是营销话术，**任务成本才是真实账单。**

*核查：✅*

### EV31. ⚪ 订阅 vs API：按场景选

订阅（包月）还是 API（按量）？按场景：

**订阅适合**：交互式使用（人坐在这打字）、重度单一用户、需要产品功能（Artifacts/联网/画图）。
**API 适合**：程序化调用（Agent/自动化流水线）、多用户产品、需要精细控制（温度/系统提示词）。

一个人两个都用是常态：白天人用订阅，晚上自动化跑 API——**人和机器各用各的通道。**

*核查：✅*

### EV32. ⚪ 模型升级的观察节奏

模型月月发布，观察节奏建议：

**发当天不看**（首日信息全是营销和服务器报错）
**第一周末看**（真实用户反馈沉淀了： strengths/ weaknesses 出现）
**第二周实测**（用你的 20 题评测集跑一遍——EV18 的模板）
**一个月后决定**（追不追、换不换）

追新有瘾，戒掉——**你的任务是做产品，不是做模型评测员**（除非评测就是你的内容，比如本号）。

*核查：✅*

### EV33. ⚪ 刷榜与榜单洗钱识别

刷榜的常见手法识别：**训练数据混入评测题**（题目原文或变体出现在训练集）、**专攻榜单题型**（只优化评测涉及的题型）、**小模型蒸馏旗舰**（排行榜分数虚高，实际能力虚）。

识别方法：看"非公开评测"（Arena 类盲测）的排名和公开榜的排名**是否一致**——公开榜高、盲测榜低的，高度可疑。

*核查：✅*

### EV34. ⚪ 领域评测：你的行业基准

通用榜单测不出领域能力——**建你自己的行业基准**：

收集 30 个你领域的真实任务（法条检索/医疗问答/电商文案…）+ 金标准答案 → 每逢新模型跑一遍 → 你的"行业榜单"就诞生了。

这个私人榜单的价值超过所有公开榜单——**它回答的是"对你的用户，谁最强"。**

*核查：✅*

### EV35. ⚪ 模型的月度体检：长期跟踪

选定的模型要**月度体检**（长期跟踪四项）：

① 你那 20 题评测集的分数（变了没有）
② 价格（API 调价公告）
③ 速度（TTFT 和吞吐，云服务会动态调整）
④ 安全性（该拒绝的还在拒绝吗）

月度体检发现异动（分数暴跌/价格暴涨/拒答率飙升）→ 及时切换备选模型。**备选模型永远要有两个。**

*核查：✅*

### EV36. ⚪ 模型组合：多模型的搭配打法

成熟用户的多模型搭配打法（各司其职）：

**日常主力**：性价比综合款（日用对话/分析）
**创意特化**：写作人味最强的（Claude 类）
**推理特化**：难题攻坚（o 系/R1 类）
**批量执行**：最便宜的小模型（分类/提取）
**本地隐私**：自部署开源款（敏感数据）

搭配的关键不是"买齐"，是**知道每个模型的长处，把对的任务给对的模型**。

*核查：✅*

### EV37. ⚪ 路由网关：多模型的自动化调度

模型多了之后，用**路由网关**自动化调度（OpenRouter/自建路由）：

按任务类型自动分发（代码任务→代码特化模型；长文档→大窗口模型）、按成本预算降级（旗舰额度用完自动切小模型）、按可用性切换（某家超时自动 fallback）。

呼应部署运维系列 DM11——**多模型的复杂度，全部关在网关这一层。**

*核查：✅*

### EV38. ⚪ 换模型的迁移成本

换模型的迁移成本，实际清单：**提示词适配**（方言差异，PE27）、**输出格式校验**（JSON 结构可能变）、**参数重调**（温度的最优值不同）、**评测重跑**（20 题集过一遍）、**应用回归测试**。

降低迁移成本的工程手段：**抽象层**（应用和模型之间加一层适配接口，换模型只改一层）。

从第一天就做抽象层——换模型的自由，是议价能力的来源。

*核查：✅*

### EV39. ⚪ 退出成本与议价能力

选型的隐藏维度：**退出成本**。

被单一厂商锁定的信号：用了私有功能（专有格式/专有工具）、数据格式不通用、提示词深度绑定方言。

保持议价能力的三件事：抽象层隔离（EV38）、评测集自持（你的数据你拿着）、备选模型常测（每月体检 EV35）。

**能随时走的客户，才拿得到最好的价格。**

*核查：✅*

### EV40. ⚪ 收束：选型的终极心法

评测选型系列 40 篇收束，终极心法三句：

**① 榜单当菜单，实测当裁决**——你的 20 题评测集比所有公开榜单都权威。
**② 分层使用，各司其职**——旗舰管判断，小模型管执行，账单和效果兼得。
**③ 保持抽象，随时能走**——议价能力来自退出成本。

模型会一直发布，价格会一直变，格局会一直洗——**选型能力（会测、会比、会换）是唯一不变的核心资产。** 本系列教的就是这个能力。

*核查：✅ 系列收束。*


## 评测工程 FAQ 篇（EV41–65，10/1）

### EV41. ⚪ 重测的时机学：什么时候必须重新评测

"上次测过没问题"是选型里最危险的一句话。四个必须重测的触发器：

一、**模型版本变化**——静默更新也好大版本也好，权重变了=重新测（M86 的教训）；

二、**价格变化**——降价周（比如这周）可能改变你的最优解：原来贵到用不起的好模型进入预算了；

三、**业务变化**——你的任务分布变了（新增了长文档场景、新语种市场），旧评测集没覆盖；

四、**季度例行**——哪怕什么都不变，每季度全量重跑一次：榜单格局、供应商策略、你自己的使用习惯都在漂。

评测不是一次性考试，是**定期体检**——体检的频率应该和"病情变化的速度"成正比，AI 行业的体检频率就是季度级。

### EV42. ⚪ 冒烟评测：20 分钟的最小可信测试

没有时间建完整评测集？20 分钟的冒烟测试版：

第一步（5 分钟）：写下**3 个本月真实发生过的任务**（不是想象的，是翻聊天记录/工单找实例）；

第二步（5 分钟）：每个任务准备 2 个变体（换个说法/加个干扰项）；

第三步（5 分钟）：新旧模型并排跑，你凭业务直觉盲排（不知道哪个是哪个）；

第四步（5 分钟）：记下结论和理由，拍照存档。

它能回答的：新模型在你的典型任务上"大概什么水平、有没有明显翻车"。它不能回答的：细粒度差距和统计显著性。

**有冒烟评测的团队，好过只有"感觉"的团队十倍**——先跑起来，再逐步进化成完整评测。

### EV43. ⚪ 评测集的防腐化：泄漏与轮换

评测集用久了会"失效"，两个机制性问题和对策：

**问题一，泄漏**——评测题目混进训练数据（特别是公开基准和热门 prompt 模板），分数虚高。对策：私有评测集不公开；核心题自创（用自己的业务实例，外面搜不到）；

**问题二，过拟合**——团队反复对着同一套评测调 prompt，评测从"考试"变成"背题"。对策：题库轮换——核心题 30 条固定（回归集），轮换题 50 条每季度换 1/3（进步集），两套分开计分。

一个自查信号：**评测分数在涨，业务指标不动**——大概率是评测被过拟合了。分数和业务结果背离时，信业务。

### EV44. ⚪ 红队即评测：把对抗测试变成日常

安全性评测不该是上线前的突击，是**每周的例行红队**：

低成本的日常红队三件套：**注入测试**（每周用新的注入话术攻击你的 Agent——"忽略之前指令"的一百种变体）、**越狱抽查**（20 条行业相关的越狱 prompt 跑一遍，看拒答率）、**边界探测**（往敏感方向推 5 轮对话，看护栏什么时候生效）。

产出物：一张"红线通过率"周报——比"我们很安全"的口头保证实在一万倍。

人手不够的替代方案：把这套测试写成脚本，接进 CI（DM 系列讲过安全扫描进 CI）——**让机器每周替你攻击自己**，攻击失败才允许发版。

### EV45. ⚪ 双盲评审：让人和 AI 同时当裁判

人工评测慢、AI 评测有偏，双盲混合评审是务实解：

流程设计：**生成匿名化**——两个模型的输出去掉身份标识、随机排序；**双轨打分**——AI 评审（用强模型按 rubric 打分）+ 人工评审（业务负责人抽查 30%）各打各的；**分歧仲裁**——两者分歧的样本进人工精审，分歧率本身就是信号（分歧大 = 任务难或 rubric 有歧义）。

关键校准：**AI 裁判要先和你的历史人工判断对齐**——拿 20 条"你团队已定调"的样本测 AI 裁判，一致率 >85% 才有资格上岗。

AI 裁判是放大器不是替代品：它让一个人能评一千条，但"什么算好"的定义权必须留在人手里。

### EV46. ⚪ 成本-质量前沿：画你自己的帕累托曲线

选型的终极可视化：把候选模型放到**成本-质量坐标系**上，画出属于你的帕累托前沿。

操作步骤：候选模型各跑一遍你的评测集（质量分），按你的月用量算月成本（成本轴），画散点图——**右上方（高质量高成本）和左下方（低质量低成本）的点里，真正值得考虑的只有"没有任何其他点比它又便宜又好"的那些**。

这张图的价值：一眼看出"溢价陷阱"（比某模型贵一倍，质量只高 2%）和"白捡的性价比"（质量几乎持平，成本砍半）。

每次价格变动（比如这周的降价潮）重画一次——**前沿会移动，你的路由表要跟着前沿走**。

### EV47. ⚪ 延迟预算：从体验倒推模型选择

选型时被忽略的硬约束：**延迟预算**。

倒推方法：从用户的体验容忍出发——客服对话场景，用户等 3 秒就烦躁 → 端到端预算 3 秒 → 减去网络和前处理，留给模型的 TTFT 预算可能只有 1.5 秒 → **超出预算的模型再聪明也出局**。

不同场景的预算参考：客服/搜索场景秒级、文档摘要十秒级、代码生成可等分钟级（有流式缓解）、批处理任务无所谓。

一个常见的架构级解法：**分级响应**——先秒级返回一个"快速版"（小模型/缓存），后台跑完整版，好了再替换。体验和质量的兼得方案，永远比二选一值钱。

### EV48. ⚪ 上下文压力测试：真实长度下的衰减测量

"支持 128K 上下文"和"128K 还能好好干活"是两回事。压力测试的做法：

**构造渐进负载**：把你的真实任务分别放在 4K / 16K / 64K / 标称上限的上下文里跑（填充物用无关但真实的文本垫），测三个指标：**指令遵循率**（开头的要求还记得吗）、**中间信息召回**（大海捞针变体，针放中间）、**输出质量分**。

实测的普遍规律（心里先有预期）：大多数模型在 50% 标称长度后开始可测量地衰减，**衰减的是"中间区域"，首尾相对坚挺**（TP59 的 Lost in the Middle）。

选型结论的写法：不说"支持长上下文"，说"**在 32K 长度下指令遵循率保持在 90% 以上**"——带条件的结论才是能用的结论。

### EV49. ⚪ 工具调用评测：function calling 的正确测法

Agent 时代的核心能力，评测却常常做错。正确的测法分三层：

**第一层，选对率**——给 20 个真实场景（配干扰项），看它选没选对工具；

**第二层，填参率**——选对工具后参数填得对不对（日期格式、枚举值、必填完整度）；

**第三层，恢复率**——故意给失败（工具报错/超时），看它会不会正确地重试、换路或求助。

大多数评测只做第一层，**第三层才是 Agent 与玩具的分水岭**——顺便说，这是微调工具调用数据时也要刻意覆盖的（FT240 的失败样例原则，评测和训练用同一个思想）。

三层各 20 题，一小时建完，但能提前暴露 Agent 上线后 80% 的尴尬。

### EV50. ⚪ 结构化输出评测：JSON 合规率的测法

依赖结构化输出（JSON/表格）的应用，评测就一条主线：**合规率**。

测法：100 次真实调用的输出，逐条过解析器——**可解析率**（能不能 load）、**Schema 合规率**（字段全不全、类型对不对）、**语义准确率**（内容对不对）。

三个实测规律先记着：一、合规率和输出长度负相关（越长越容易断）；二、中文引号/换行符是 JSON 杀手（预处理转义能救回来）；三、API 的"结构化输出模式"合规率普遍在 99%+，纯 prompt 约束的普遍在 90-97%——**差的那几个点，就是半夜告警的来源**。

阈值建议：可解析率低于 99% 的方案，不配上生产（配上重试和兜底另说）。

### EV51. ⚪ 多语言评测：小语种的抽查法

做国际市场（比如出海）的选型，多语言评测用抽查法：

**抽样策略**：别测全语种，测你的**真实市场组合**——主力语言全测，长尾语言抽查。每个语言 10 题：5 题从你的真实语料抽、3 题文化语境（节日/法规/俗语）、2 题指令遵循。

**一个隐藏指标**：让模型"用目标语言解释目标语言的文化现象"——这比翻译题更能暴露训练语料的深度（翻译好≠文化懂）。

**成本警告**：小语种的 tokenizer 压缩率普遍差（TP51），同任务 token 成本可能是英文的 2-3 倍——**评测时顺便记 token 消耗**，别上线后才发现账单翻倍。

### EV52. ⚪ 长任务评测：跨轮次的一致性追踪

多轮长任务（比如一个 20 轮的客服会话、一个 10 步的 Agent 流程），评测的不是单轮质量，是**跨轮一致性**：

三个追踪指标：**指令遗忘率**（第 15 轮还记得第 1 轮的格式要求吗）、**事实漂移**（前面说的数字后面会不会变）、**目标完成率**（整个任务跑完，最初的目标达成了吗）。

测法：把你的真实长对话/长流程样本做成脚本回放，末端自动校验——**人肉测长任务太贵，脚本化是唯一可持续的方式**。

实测预判：所有模型在 10 轮以上都会出现可测的指令遗忘——**差距不在"会不会忘"，在忘得快慢**。对策不是换模型，是中途重申（M96）+ 分段（M96 的三解法）。

### EV53. ⚪ 幻觉率测量：引用可回溯率

幻觉的测量，务实的指标是**引用可回溯率**：

定义：模型输出里的每个事实性陈述，能在给定资料（RAG 召回/上传文档）中找到出处的比例。

测法：从真实输出里抽 50 条，人工逐句标注"有出处/无出处/编造"——一小时的工作量，换来你的应用最真实的安全画像。

分层解读：**编造率**（说了资料里没有的东西）是最危险的，**遗漏率**（资料有但没说）只是质量问题——两个率分开统计，改善动作完全不同（编造靠约束和-grounding，遗漏靠召回优化）。

给 RAG 应用的及格线参考：编造率 <2%，可回溯率 >95%——**达不到先别谈效果，先谈安全**。

### EV54. ⚪ 安全评测的分层：内容、行为、隐私

安全评测不是一个大分数，是三层分开测：

**内容层**——不该说的说不说：敏感请求的拒答率、价值观的一致性（SC 系列的红线集）；

**行为层**——不该做的不做：Agent 的权限边界（会不会越权调用工具）、注入的抵抗（提示注入成功率）——**行为层比内容层危险一个量级**，因为损害是真实的动作；

**隐私层**——不该记的不记：训练数据记忆探测（模型会不会吐出训练时的个人信息）、会话隔离验证（这个会话的内容会不会影响那个会话）。

三层各建 20 题的最小集，**行为层的优先级最高**——内容出错是口碑问题，行为出错是赔偿问题。

### EV55. ⚪ 微调前后对照：评测驱动的迭代节奏

微调项目里评测的角色，是**迭代的节拍器**：

标准节奏：**基线测**（微调前，原模型跑一遍进步集+回归集）→ **每 checkpoint 测**（训练中每个存档点跑回归集，防遗忘）→ **终测**（训完跑全量）→ **上线后月测**（真实流量抽样回归）。

节奏的价值在对照：**"微调后 vs 基线"的差值**才是微调的真实贡献——没测过基线的微调，效果全靠讲故事。

工具提示：评测脚本和训练脚本放同一个仓库、同一个 CI——**每次训练自动触发评测**，人只需要看报表。评测不是训练之后的步骤，是训练流程的一部分。

### EV56. ⚪ 评测报告模板：一页纸讲清选型

评测做完，怎么写报告让决策者三分钟看懂？一页纸模板：

**第一行，结论**：推荐 X 模型，用于 Y 场景，替换/保留 Z——一句话，别铺垫；

**第二块，三行表**：质量分（你的评测集）、月成本（按你的用量）、最大风险（一两句）；

**第三块，取舍说明**：为什么不是分数最高的那个（通常是成本或延迟）、放弃了什么；

**第四块，复测计划**：什么时候、什么条件下重测。

反模式警告：**评测报告不是论文**——过程和数据放附录，决策者只看第一行。写了几页没人读的报告，等于评测白做。

### EV57. ⚪ 价格谈判：用量数据的准备

企业级采购模型 API，谈判的筹码是**你的用量数据**：

谈判前准备好三张表：**用量画像**（月调用量、token 分布、峰谷时段——证明你是值得给折扣的客户）、**替代方案报价**（竞品同规格的报价单——比"我在考虑别家"的空话有力十倍）、**增长承诺**（未来 6 个月的量预测——供应商给折扣买的是你的未来）。

折扣的合理预期：公开价的 7-9 折是常规空间，承诺年约+用量可谈到 6-7 折——**但折扣换承诺，每一条承诺都写进合同**。

这周正好是价格战窗口（Sol 降价、新玩家入场）——**你的续约谈判，现在就是最好的时机**。

### EV58. ⚪ PoC 的设计：两周验证一个模型

正式评测前的 PoC（概念验证），两周的设计模板：

**第一周·跑通**：Day 1-2 接 API 跑通最小流程；Day 3-5 用 10 个真实任务手动对比现役方案；Day 6-7 记录翻车案例。

**第二周·压测**：Day 8-9 上量测试（100 个任务批量跑 + 成本核算）；Day 10 边界测试（超长输入/异常输入/并发）；Day 11-12 出结论（对照 EV56 的模板）。

**PoC 的三条纪律**：真实任务（演示任务测不出真相）、记录失败（成功案例会骗人，失败案例不会）、到期就砍（PoC 超期=需求不清，停下来重想）。

两周出不了结论的 PoC，结论大概率是"不合适"——**快速说不，也是 PoC 的价值**。

### EV59. ⚪ 模型替换演练：备用模型的彩排

备用模型不是"知道有这个东西"就行，是**演练过的退路**：

季度演练清单：**切换脚本真的跑一遍**（改配置→全量切到备用模型→核心功能验证→切回，全程计时）；**备用模型过评测**（你的回归集在备用模型上跑一遍，质量心里有数）；**差异清单维护**（主备模型的行为差异记录——格式偏好、参数习惯、安全边界的不同）。

一个残酷的现实校验：**没演练过的备用方案 = 没有备用方案**——出事那天你会发现切换脚本过期了、备用模型降价了下架了、或者质量根本不行。

季度半天，买一份"任何时刻可搬家"的自由——这是基础设施运维（DM）和模型选型（EV）的交叉必修课。

### EV60. ⚪ 供应商健康度：怎么看模型厂商的稳定性

选模型也是选供应商，健康度的观察清单：

**API 稳定性**（第三方监控站点的可用率历史，不是厂商自己的宣传）、**版本节奏**（更新频率是规律还是随机——静默更新多的厂商要配更严的回归监控）、**文档质量**（changelog 是否及时详细——文档懒的团队运维也懒）、**财务与战略**（烧钱速度、融资状态、产品线收缩迹象——免费产品突然收费、热门功能突然下线都是信号）、**社区温度**（开发者社区的抱怨类型和官方响应速度）。

**红色信号清单**：核心团队离职潮、企业版功能挤牙膏、API 条款频繁变更、竞品发布时跑分造假被拆穿——**出现两条以上，启动你的备用模型演练（EV59）**。

### EV61. ⚪ 评测的成本控制：别让评测比业务贵

评测本身的成本会失控，三个控制阀：

**抽量评测**——不需要每次全量：回归集每次全跑（30 条），进步集抽样跑（50 条里抽 20），全量只在季度大检；

**缓存评测**——固定输入的评测结果缓存，同版本不重跑（模型没变、prompt 没变，重跑是浪费）；

**分级裁判**——AI 裁判初筛（便宜）+ 人工仲裁（贵而少），人工预算只花在分歧样本上（EV45 的机制）。

成本核算的参照：**评测月成本 ≤ 模型调用月成本的 10%**——超过了说明评测设计过度，砍题或降频。

评测是保险，不是另一门生意——**保费别超过保额**。

### EV62. ⚪ 团队评测规范：多人打分的一致性

多人参与评测的团队，一致性是生命线（FT244 讲过标注规范，这里讲评测特供版）：

**评分标准操作化**——"好"的定义写成可判定的清单（"回答了所有子问题 = 1 分"而不是"回答得不错"）；**校准样本**——每次评测开头先打 5 条历史校准题（团队已有共识的样本），偏差大的评分员重新读标准；**一致性度量**——两人交叉评 20 条，一致率 <75% 就停下重新对齐标准（别硬着头皮评完）；**盲评纪律**——评分员不知道输出来自哪个模型，知道身份的评分叫粉丝投票。

一致性差的团队评测，噪声比信号大——**先修标准，再采数据**。

### EV63. ⚪ 评测数据的复用：从选型到监控

评测资产的一次投入、三次复用：

**第一次，选型**（本系列的原始用途——对比候选模型）；**第二次，监控**（同一套评测集接进线上，月度跑一遍当"回归体检"——EV41 的季度体检自动化版）；**第三次，训练**（评测集里人工标注的"好答案"样本，就是微调的训练数据——FT118 评测集构建和 FT 系列的数据工程在这里闭环）。

反过来说：**建评测集时就想好三次复用**——题目带标准答案、样本带真实分布、标注带业务理由，这样的评测集才是资产，不然只是开销。

一份数据的用途越多，它的单次成本越低——评测预算紧张时，先补"复用性"，再补"题量"。

### EV64. ⚪ 新模型 24 小时接入清单

新模型发布日（这周就有两次），从围观到可用的 24 小时清单：

**第 1 小时**：读官方博客的 changelog 部分（跳过营销段落），确认 API 兼容性和价格表；

**第 2-4 小时**：接入测试环境（一行配置的事，抽象层此时兑现价值），跑冒烟评测（EV42）；

**当天下午**：过安全红线集（EV54 的 20 题）——**新模型的安全边界是黑盒，先测再夸**；

**24 小时内**：出"是否进入路由表"的初步结论——进（哪个场景用）、不进（等哪个信号再评）、观望（等第三方实测）。

**纪律**：48 小时内不进生产——发布日的演示和一周后的真实表现，经常是两个故事。

### EV65. ⚪ 收束：评测体系的总图

选型系列第二次收束，把 65 篇收进一张总图：

**资产层**——你的评测集（EV18/43：进步集+回归集，防泄漏防过拟合）+ 你的用量数据（EV57：谈判与成本决策的底牌）；

**方法层**——冒烟（EV42）→ 完整评测（EV46-53：成本质量前沿、延迟预算、压力测试、工具调用、幻觉率）→ 报告（EV56）；

**运营层**——重测节奏（EV41）、供应商健康度（EV60）、替换演练（EV59）、成本控制（EV61）；

**团队层**——规范与一致性（EV62）、数据复用（EV63）、24 小时接入流程（EV64）。

一句话总纲：**评测不是给模型打分，是给你的业务装仪表盘**——分数是仪表，决策是方向盘。

40 条讲选型，25 条讲工程——选型的尽头不是选出一个赢家，是**建成一套让任何新玩家进来都能被快速评估的体系**。体系在手，天下模型任你评。
