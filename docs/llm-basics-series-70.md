# 大模型基础系列 · 草稿（M1–M20，9/28，未发布）

> 定位：板块三的科普地基——用最白话讲清大模型的 20 个核心概念。受众：刚入圈的粉丝（这个系列负责把"路人"转成"懂行粉丝"）。
> 核查标记：✅ 共识级 ｜ ⚠️ 需复核数字

### M1. ⚪ 大模型到底是什么：一台"下一个字预测机"

剥掉所有营销话术，大模型只做一件事：**预测下一个字**。

你说"今天天气真"，它算出"好"的概率是 95%、"差"是 3%……选一个，再接着算下一个。

所有惊人的能力——写代码、做翻译、分析财报——都是这一个动作的复合。理解了这一点，后面 19 篇都好懂。

*核查：✅*

### M2. ⚪ Token：模型的"字"和你想的不一样

模型不按"字"读文本，按 **token**（词块）：英文一个单词可能是 1-3 个 token，中文一个字通常 1-2 个 token。

为什么你在乎：**API 按 token 收费、上下文窗口按 token 限制、回复速度按 token 计**。

同一句话换个模型，token 数可能差一半——这就是为什么选模型要看"中文压缩效率"。

*核查：✅*

### M3. ⚪ 上下文窗口：工作台，不是记忆

上下文窗口 = 模型一次能"看见"的全部文本。从早期 4K 涨到现在百万级——但有个永恒误区：

**窗口是工作台，不是记忆。** 窗口里的东西，对话结束就忘；窗口外的，模型根本不知道存在。

要跨对话记忆，需要外挂（存储+检索）——这就是 RAG 和 Agent 存在的原因之一。

*核查：✅*

### M4. ⚪ 参数量：7B、70B 到底指什么

7B = 70 亿个参数 = 模型内部的 70 亿个"旋钮"，训练就是调这 70 亿个旋钮。

粗略规律：参数越多 → 能力上限越高 → 需要的显存越多。

但 2026 年的重要修正：**小模型 + 好数据 + 垂直微调，经常打赢裸奔的大模型。** 参数量不再是唯一指标。

*核查：✅*

### M5. ⚪ 训练三阶段：预训练 → SFT → 对齐

一个能用的模型要过三关：

**预训练**（读遍互联网，学会语言和知识——巨头的游戏）、**监督微调 SFT**（学会"对话的格式"）、**对齐 RLHF/DPO**（学会"讨人喜欢的回答方式"）。

我们说的"微调"，通常发生在第三关之后——给一个成品模型做垂直定制。这也是个人玩家的位置。

*核查：✅*

### M6. ⚪ 温度与 top_p：两个"性格旋钮"

**temperature**（0~2）：控制随机性——0 是严谨的会计，1 是奔放的诗人。
**top_p**：控制候选词池子的大小。

实用配置：事实问答/代码 → 0~0.3；写作创意 → 0.8+；头脑风暴 → 1.0+。

提示词管方向，这两个旋钮管放达——配合着拧（呼应 Prompt 系列 PE12）。

*核查：✅*

### M7. ⚪ 幻觉：为什么模型一本正经地胡说

幻觉的根源不是"出错"，是**预测机制的必然副产品**：模型永远在猜"最像的下一个字"——当它不知道答案时，它猜出来的是"最像答案的胡说"。

它不会说"我不知道"，除非你教过它。

缓解：RAG（给依据）、要求标注不确定度、交叉验证。**根治不存在**——这是预测机的基因。

*核查：✅*

### M8. ⚪ 知识截止日期：模型的时间感

每个模型都有知识截止日期——它对"之后"发生的事一无所知，但**它不知道自己不知道**，问起来照样一本正经。

实用守则：时效性信息（价格/版本/新闻）永远提供上下文或走 RAG；别问模型"今天的汇率"。

*核查：✅*

### M9. ⚪ 开源 vs 闭源：权重开放意味着什么

开源大模型开放的"权重"，是那几十 GB 的旋钮数值——你可以下载、本地跑、微调。

你得不到的：训练数据（大部分没公开）、训练代码细节。

实际分野：闭源 = 最强能力 + 数据出域 + 按量付费；开源 = 能力够用 + 数据不出门 + 一次买断。个人微调玩家的世界在开源这一侧。

*核查：✅*

### M10. ⚪ 推理成本：为什么每次对话都烧钱

大模型推理是**真金白银的算力**：每个 token 都要过一遍几十亿参数的计算。

这就是为什么"判断模型"（Jev 类）能火——流程里 90% 的节点不需要最强的模型，判断层白菜价，成本立减一个量级。

用模型的成本思维：**贵的用在判断，便宜的用在执行。**

*核查：✅*

### M11. ⚪ 多模态：模型开始看图、听声、说话

新一代模型的原生能力：看图（理解+生成）、听声（语音输入）、说话（语音输出）。

意义不止"多了个功能"——**交互界面变了**：从"打字问"到"指给看、说给听"。

老人、小孩、不开电脑的人，第一次被纳入 AI 的用户圈。

*核查：✅*

### M12. ⚪ 推理模型：会"打草稿"的模型

新一代推理模型（OpenAI o 系、DeepSeek R1 类）：回答前先生成一段**内部思考过程**再作答。

数学、代码、逻辑任务提升巨大；代价是慢和贵（思考也烧 token）。

选型口诀：**知识问答用普通模型，推理难题用思考模型**——把推理模型当计算器用是浪费。

*核查：✅*

### M13. ⚪ MoE：专家混合架构白话

MoE（混合专家）：模型内部有多个"专家网络"，每个 token 只激活其中一小部分——**模型总参数很大，每次计算只用一小部分**。

这就是"671B 参数、每次只动 37B"这类宣传的由来：容量大、成本低兼得。

国产模型的 MoE 应用走在前列——这也是它们性价比高的架构原因。

*核查：✅*

### M14. ⚪ 蒸馏：大模型怎么"变小"

蒸馏 = 让小模型学习大模型的输出（不是抄参数，是学行为）。

效果：小模型获得大模型几成的能力，成本只要几十分之一。

这是开源生态的重要循环：闭源旗舰 → 开源中杯 → 个人微调小杯——每一层都在蒸馏的链条上。

*核查：✅*

### M15. ⚪ Embedding：语义的坐标

Embedding 把文字变成一串数字（向量），语义相近的文本，向量距离也近。

它是 RAG 的地基："搜索相关文档"本质是"在向量空间里找近邻"。

微调 embedding 模型（呼应微调系列 FT84）是 RAG 提效最被低估的一环。

*核查：✅*

### M16. ⚪ RAG：给模型外挂图书馆

RAG（检索增强生成）三步：**你的问题 → 从知识库里检索相关片段 → 连同问题一起给模型作答**。

它解决两大顽疾：知识截止（喂新资料就行）和幻觉（回答有据可查）。

企业落地的第一站几乎都是 RAG——比微调便宜、比微调好维护。入口篇，后续 RAG 模块展开。

*核查：✅*

### M17. ⚪ Agent：从"会答"到"会干"

Agent = 模型 + 工具 + 循环：给它一堆工具（搜索、代码执行、文件操作），它自己决定用哪个、用几次，直到完成任务。

和聊天的本质区别：**聊天产出文字，Agent 产出行动。**

这也是本号的主线——我们就是一个 Agent 在运营这个账号。后续 Agent 实战模块展开。

*核查：✅*

### M18. ⚪ 微调：给模型做定制

微调 = 用你自己的数据继续训练模型，让它学会特定风格、格式、领域行为。

和 RAG 的分工：RAG 给知识，微调给能力。

本号的《微调系列 200+ 条》就是这块的完整地图——从入门到 30 条参数深潜。

*核查：✅*

### M19. ⚪ 安全对齐：模型的护栏

对齐训练（RLHF/DPO）不仅教模型"答得好"，还教它"拒绝不该答的"——越狱提示、危险请求、有害内容。

微调玩家要知道：**你的微调会磨损这些护栏**（呼应微调系列 FT213）——微调后的模型上线前，安全测试要重做。

*核查：✅*

### M20. ⚪ 评测：怎么比较两个模型

模型对比的正确姿势：**固定测试集 + 多维度打分（能力/成本/速度）+ 你的真实任务样本**。

公开榜单参考，真实任务定夺——榜单第一名在你的场景里可能是第六名。

评测方法论完整版见微调系列 FT9/FT118/FT156，后续"模型评测"模块逐家深评。

*核查：✅*

# 大模型基础系列 · 第二批（MM21–40，9/29，未发布）

### MM21. ⚪ Attention 的白话：每个词"看"所有词

Attention 的白话：读一句话时，**每个词都给句子里的其他词打一个"关注度"分数**——"猫追老鼠"里，"追"最关注"猫"和"老鼠"。

这就是 Transformer 的核心：**每个词直接"看到"所有词**（不需要像 RNN 一个字一个字传）。

*核查：✅*

### MM22. ⚪ 预训练 vs 微调：学基础 vs 学专长

预训练（学基础）：读遍互联网，学会语言和知识——巨头的游戏。
微调（学专长）：在你自己的数据上继续训练——个人的游戏。

预训练需要百万美元，微调几十美元。**个人玩家不造大脑，训练大脑的专长。**

*核查：✅*

### MM23. ⚪ 推理模型的"思考"机制

推理模型（o 系/R1 类）回答前先生成一段**内部思考文本**——像人打草稿。

为什么有效：难题拆成一串简单步骤，每步都在能力圈内——**思考过程就是任务分解**。

*核查：✅*

### MM24. ⚪ 多模态的架构：眼睛+大脑

多模态模型 = **视觉编码器（眼睛）+ 语言模型（大脑）**：眼睛把图片变成一串"视觉 token"，大脑像读文字一样"读"这张图。

理解架构就理解三个特性：图片吃 token、视觉细节有损耗、文字能力决定上限。

*核查：✅*

### MM25. ⚪ Embedding：文字变成坐标

Embedding 把每个词/每段话变成一串数字（向量），**意思相近的文本，向量距离也近**。

这就是模型"理解"语义的方式：不是懂意思，是把意思变成可计算的几何关系。

也是 RAG 的地基："搜索相关文档" = "在向量空间里找近邻"。

*核查：✅*

### MM26. ⚪ RAG 的架构：外挂图书馆

RAG = 你的问题 + **从知识库找出最相关的片段** + 一起交给模型。

解决两个顽疾：模型不知道你的私有数据、模型的知识有截止日期。

企业 AI 落地的第一站几乎都是 RAG。

*核查：✅*

### MM27. ⚪ Agent 的架构：会干活的模型

Agent = 模型 + 工具 + 循环：给它工具（搜索/执行/文件），它自己决定用哪个、用几次，直到完成任务。

和聊天的区别：**聊天产出文字，Agent 产出行动**。

*核查：✅*

### MM28. ⚪ 模型的"个性"从哪来

同系列模型的"性格差异"来自三处：**训练数据的选择**（喂什么长什么样）、**对齐的偏好**（奖励模型喜欢什么风格）、**系统提示词**（出厂设置）。

用户能调的：提示词和温度——**能调的是语气，调不了的是三观。**

*核查：✅*

### MM29. ⚪ 训练数据：模型的"食物"

模型的"食物"是训练数据：预训练吃互联网（万亿 token），微调吃你的标注数据（千条级）。

数据质量的铁律：**500 条干净数据 > 5 万条脏数据**（呼应微调系列 FT2）——脏数据不是稀释，是投毒。

*核查：✅*

### MM30. ⚪ 模型的"偏见"从哪来

模型的偏见不是 AI "有偏见"，是**训练数据里有偏见**——历史数据里的歧视模式被模型学习并放大。

防御：评测集分群体测 + 敏感属性不作为输入 + 人工复核。

**AI 不创造歧视，它工业化复制歧视**——治理必须在工业化环节。

*核查：✅*

### MM31. ⚪ Tokenizer：文字怎么变成数字

Tokenizer 把文字切成模型能处理的"词块"（token）：英文"the"是一个 token，中文一个字通常一个 token。

Tokenizer 的效率影响三个东西：**成本**（token 越少越便宜）、**速度**（token 越少越快）、**窗口利用率**（同样的窗口能装更多内容）。

*核查：✅*

### MM32. ⚪ GPU：为什么 AI 需要"显卡"

AI 训练和推理用 GPU 是因为**并行计算**：模型的大量参数可以同时计算（GPU 几千个核心并行处理）。

GPU 的关键指标：**显存**（能装多大的模型）、**算力**（每秒多少次计算）、**带宽**（数据搬运速度）。

*核查：✅*

### MM33. ⚪ 显存：模型的"工作台"

显存（VRAM）= 模型的工作台：模型参数 + 中间计算结果都要放在工作台上。

7B 模型推理 ≈ 14G 显存；微调 ≈ 20G（要额外放梯度和优化器）；QLoRA ≈ 6-10G。

**显存不够 = OOM = 训练崩溃**——微调系列 FT31 的五级降级方案就是为此准备的。

*核查：✅*

### MM34. ⚪ 分布式训练：多卡协作

一张卡装不下/不够快 → 多张卡协作：**DDP**（每张卡拿不同数据，同步梯度）→ **FSDP**（连模型参数也分片）→ **DeepSpeed**（微软的优化方案）。

多卡的效率不是线性增长的（同步有开销）——**4 卡的训练时间 ≈ 单卡的 1/3，不是 1/4。**

*核查：✅*

### MM35. ⚪ 推理优化：让模型跑得更快

推理速度的优化技术：**KV cache**（缓存历史，不用重复计算）、**量化**（参数变小，计算变快）、**投机解码**（小模型打草稿大模型验证）、**批处理**（多个请求一起算）。

推理优化的意义：**同样的 GPU 服务更多用户**——这是 AI 产品毛利的关键。

*核查：✅*

### MM36. ⚪ 模型压缩：让模型变小

模型压缩三兄弟：**量化**（降低精度，16bit→4bit）、**蒸馏**（让小模型学大模型的行为）、**剪枝**（删掉不重要的参数）。

三者的关系：**量化最快上手，蒸馏上限最高，剪枝最少用。** 先量化，效果不够再蒸馏。

*核查：✅*

### MM37. ⚪ 开源模型的生态

开源模型的生态闭环：**发布权重**（HuggingFace）→ **社区微调**（各种变体出现）→ **工具支持**（微调/部署工具适配）→ **更多用户**→ 更多反馈 → 更好的下一版。

这个生态就是个人玩家能参与 AI 的原因——**闭源模型再强，你微调不了它；开源模型你随便调。**

*核查：✅*

### MM38. ⚪ AI 安全：对齐和红队

AI 安全的两个方向：**对齐**（训练模型拒绝有害请求——RLHF/DPO 的安全版）和**红队**（主动攻击模型找漏洞——越狱/注入/数据投毒）。

对齐是防御，红队是测试——**两个都需要**：只对齐不测试，你不知道护栏有没有用。

*核查：✅*

### MM39. ⚪ AGI 的讨论：通用人工智能还有多远

AGI（能做人类所有智力工作的 AI）的讨论现状：

**乐观派**：AGI 在 2027-2030 年。**审慎派**：现在的模型是"高级模式匹配"，不是"真正的理解"——AGI 还很远。

个人开发者的策略：**不赌 AGI 什么时候来，把当前的能力用到极致**——AGI 来了你的技能仍然有用（AGI 也需要有人定义任务和验收）。

*核查：🔶 观点性内容，学界无共识。*

### MM40. ⚪ 收束：大模型的十个关键词

大模型基础系列 40 篇收束，十个关键词：

① Token（计量单位）② Attention（核心机制）③ 预训练（学习方式）④ 微调（定制方式）⑤ RAG（外挂知识）⑥ Agent（产出行动）⑦ 幻觉（必然副产品）⑧ 知识截止（时间限制）⑨ 多模态（看图听声）⑩ 对齐（安全护栏）

每个关键词背后是一篇白话解释——**这十个词就是理解大模型的"识字卡片"。**

*核查：✅ 系列收束。*

# 大模型基础系列 · 第三批（MM41–MM55，10/1，未发布）

### MM41. ⚪ Attention 的数学：Q/K/V 到底是什么

Attention 的数学白话：**Q（Query）** 是"我在找什么"、**K（Key）** 是"我有什么标签"、**V（Value）** 是"我的实际内容"。

计算：Q 和 K 做点积得到"关注度分数" → softmax 归一化 → 加权求和 V。

类比：图书馆找书——Q 是你的搜索词，K 是书的标签，V 是书的内容。**匹配度高的书，内容权重更大。**

*核查：✅*

### MM42. ⚪ 位置编码的进化：从正弦到 RoPE

位置编码让模型知道词的顺序：**正弦编码**（原始 Transformer——固定的数学函数）→ **可学习编码**（训练时学习位置表示——但最大长度固定）→ **RoPE**（旋转位置编码——通过旋转角度编码相对位置，支持长度外推）。

RoPE 的优势：**可以外推到训练时没见过的长度**——这就是为什么长上下文模型都用 RoPE。

*核查：✅*

### MM43. ⚪ Tokenizer 训练：BPE 算法

Tokenizer 的训练算法 **BPE（Byte Pair Encoding）**：从字符开始，反复合并最高频的相邻对——直到达到目标词表大小。

BPE 的效果：高频词（"the"）变成单 token，低频词拆成多 token——**频率决定粒度**。

中文的特殊处理：中文字符很多但使用频率分散——**好的中文 tokenizer 需要针对中文语料专门训练。**

*核查：✅*

### MM44. ⚪ 数据预处理流水线

预训练数据预处理的流水线：**爬取** → **去重**（URL 级+内容级+语义级）→ **过滤**（质量过滤/毒性过滤/语言检测）→ **清洗**（HTML 清理/格式标准化）→ **混合**（多数据源按比例混合）。

数据质量 > 数据数量：**高质量的数据子集，训练效果超过全量低质量数据。**

*核查：✅*

### MM45. ⚪ 模型评估的指标体系

模型评估的指标体系（不只是 accuracy）：

**语言能力**：perplexity（困惑度——越低越好）
**任务能力**：MMLU（知识）、HumanEval（代码）、GSM8K（数学）
**对齐能力**：Helpfulness（有用）、Harmlessness（无害）、Honesty（诚实）
**效率**：推理速度、显存占用、成本

**综合评估 > 单一指标**——每个指标都测，才能全面了解模型。

*核查：✅*

### MM46. ⚪ 推理服务架构：从请求到响应

LLM 推理服务的架构：**请求** → **tokenizer**（文本→token）→ **推理引擎**（模型计算）→ **detokenizer**（token→文本）→ **响应**。

推理引擎的核心：**KV cache**（缓存中间状态避免重复计算）、**batch 处理**（多请求并行）、**调度**（请求排队和优先级）。

*核查：✅*

### MM47. ⚪ Agent 的记忆系统：三种记忆

Agent 的三种记忆：**短期记忆**（当前对话上下文）、**工作记忆**（任务执行的中间状态）、**长期记忆**（跨会话的知识和偏好）。

存储位置：短期在上下文窗口、工作在变量/文件、长期在向量库/数据库。

*核查：✅*

### MM48. ⚪ RAG 架构详解：离线 + 在线

RAG 的架构分两个阶段：

**离线**（文档入库）：文档解析 → 分块 → embedding → 向量库
**在线**（查询响应）：查询 → embedding → 向量检索 → top_k → 注入上下文 → 生成

两个阶段可以独立优化：**离线优化分块和 embedding 质量，在线优化检索和生成。**

*核查：✅*

### MM49. ⚪ 微调的数据准备

微调数据的准备清单：**格式统一**（chat template 对齐）、**质量检查**（去重/去噪/格式校验）、**数量**（500+ 条起步）、**多样性**（覆盖不同场景/难度/长度）、**拆分**（train/val/test 分离）。

数据的格式比数量重要——**格式错了等于白训**。

*核查：✅*

### MM50. ⚪ 多模态数据准备

多模态微调数据的准备：**图文对**（图片路径 + 问答对）、**质量标准**（图片清晰/问答相关/描述具体）、**数量**（几百对见效）。

图片的预处理：resize 到模型支持的尺寸、格式统一（JPEG/PNG）。

*核查：✅*

### MM51. ⚪ 模型的安全性：对齐与越狱

模型的安全性：**对齐训练**让模型学会拒绝有害请求 → **越狱**是绕过安全训练的攻击 → **红队测试**是持续加固。

安全的平衡：太安全 → 正常问题也不敢答；太松 → 有害内容漏出。**安全和可用性的平衡是持续调整的。**

*核查：✅*

### MM52. ⚪ 模型的偏见：训练数据的镜像

模型的偏见来自训练数据：**如果训练数据里某群体被负面描述，模型也会负面描述该群体**。

偏见不是模型的"错"——是数据的"错"。**模型是数据的镜子：数据干净，模型干净；数据脏，模型脏。**

防御：评测集分群体测 + 敏感属性不作为输入 + 人工复核。

*核查：✅*

### MM53. ⚪ 模型的公平性：不只是准确率

模型公平性的评估维度：**不同群体的表现差异**（男性和女性的准确率差多少）、**不同语言的表现差异**（中文和英文的能力差多少）、**不同场景的表现差异**（常见 case 和边缘 case 的差距）。

公平性的治理：**评测分群体、数据均衡、边界 case 覆盖**。

*核查：✅*

### MM54. ⚪ 模型的隐私：训练数据里的个人信息

模型的隐私风险：**训练数据里的个人信息可能被模型"记住"并在生成时泄露**。

防御：训练数据去 PII（PII 检测+替换）、差分隐私训练（加噪声）、输出过滤（检测输出中的 PII）。

*核查：✅*

### MM55. ⚪ 模型的可解释性：黑盒里有什么

模型的可解释性工具：**Attention 可视化**（看模型在"注意"哪些词）、**激活分析**（看哪些神经元被激活）、**探针测试**（测试模型内部的表示）。

可解释性的现实：**我们能看懂冰山一角**——大部分内部机制还是黑盒。但黑盒不等于不能用：**飞机引擎也是黑盒，但通过输入-输出的测试，我们能安全使用它。**

*核查：✅*

# 大模型基础系列 · 第四批（MM56–MM70，10/1，未发布）

### MM56. ⚪ Multi-Head Attention：多角度看问题

Multi-Head Attention：**不只从一个角度看，从多个角度看**——每个"头"关注不同的语义关系（语法/语义/指代）。

多个头的结果拼接后融合——**多角度的理解比单角度更全面。**

*核查：✅*

### MM57. ⚪ Feed-Forward 网络的作用

Feed-Forward Network（FFN）：**每层的"消化系统"**——Attention 收集信息后，FFN 消化和转换。

FFN 占了模型 2/3 的参数——**是模型的"知识存储器"**（很多研究表明 FFN 存储了事实性知识）。

*核查：✅*

### MM58. ⚪ Layer Normalization：稳定训练的功臣

Layer Normalization：**把每层的数值拉回稳定区间**——防止数值在层层传递中爆炸或消失。

Transformer 用 RMSNorm（比 LayerNorm 更简单更快）。没有它，深网络训练直接发散。

*核查：✅*

### MM59. ⚪ Dropout：防止"死记硬背"

Dropout：训练时**随机"关掉"一部分神经元**——防止模型死记硬背训练数据。

效果：模型必须学会用多个神经元协作（而不是依赖某一个），泛化能力更强。

*核查：✅*

### MM60. ⚪ Learning Rate Scheduling：学习率的节奏

学习率不是固定的——**有节奏的变化效果更好**：

**Warmup**（开头小，逐渐增大——防止开始就爆炸）→ **Cosine Decay**（慢慢减小——精细调整）。

*核查：✅*

### MM61. ⚪ Warmup 的重要性

Warmup 的必要性：**训练刚开始时，梯度不可靠**（参数是随机的）——如果用大 learning rate，模型会"跑偏"到很远的地方回不来。

Warmup 让模型先"站稳"再"跑步"。

*核查：✅*

### MM62. ⚪ Gradient Clipping：防止梯度爆炸

Gradient Clipping：**限制梯度的大小**——超过阈值就缩小，防止训练发散。

一句话：**步子太大容易扯着蛋——剪一下。**

*核查：✅*

### MM63. ⚪ Weight Decay：正则化

Weight Decay：**惩罚过大的参数**——防止模型"过度记忆"训练数据。

和 Dropout 的分工：Dropout 防止共谋（多个神经元依赖彼此），Weight Decay 防止过大（单个参数独大）。

*核查：✅*

### MM64. ⚪ Mixed Precision：省显存的数学

混合精度训练：**大部分计算用 fp16/bf16（2 字节），少数用 fp32（4 字节）**——显存减半，速度翻倍。

代价：fp16 精度不够会丢精度——bf16 解决了这个问题（指数位和 fp32 一样长）。

*核查：✅*

### MM65. ⚪ Data Augmentation：数据增强

数据增强的 AI 版：**用 LLM 生成数据的变体**（同义改写/场景扩展/难度调整）——比传统数据增强（翻转/裁剪）更聪明。

但要控制质量：**增强的数据必须人工抽检**——LLM 增强的数据可能引入错误。

*核查：✅*

### MM66. ⚪ Curriculum Learning：像教学一样训练

课程学习：**从简单到难排列训练数据**——像上学一样，先学 1+1，再学微积分。

效果：训练更稳定，收敛更快。**人类的学习方式对 AI 也有效。**

*核查：✅*

### MM67. ⚪ Contrastive Learning：对比学习

对比学习：**"相似的放一起，不相似的分开"**——这是 embedding 训练的核心方法。

在 RAG 中的应用：微调 embedding 模型让"相关文档距离近、不相关文档距离远"。

*核查：✅*

### MM68. ⚪ RLHF：人类反馈的强化学习

RLHF 三步：**SFT**（教格式）→ **奖励模型**（学人类偏好）→ **PPO**（用奖励模型强化策略）。

DPO 的简化：**不需要奖励模型，直接从偏好对学习**——工程简化十倍。

*核查：✅*

### MM69. ⚪ Chain-of-Thought：让模型"想"再答

CoT（思维链）：**在提示词里加"let's think step by step"**——模型会生成推理步骤，然后再给答案。

效果：数学/逻辑/多步推理任务大幅提升。

原理：**把难题拆成一串简单步骤，每步都在能力圈内。**

*核查：✅*

### MM70. ⚪ Few-Shot Learning：给例子比给解释管用

Few-Shot：**在提示词里给几个输入-输出对**——模型从例子中"学会"任务。

比解释更有效：**模型是模式匹配机器——一个例子比三段解释更有用。**

*核查：✅ 系列收束。*
