# 大模型技术原理白话系列 · 草稿（TP1–TP40，9/28，未发布）

### TP1. ⚪ 神经网络的直觉：从人脑到人工

神经网络的直觉版：**很多个简单的"开关"连成网络，每个开关接收上游信号、加权求和、超过阈值就激活**。

单个开关很笨（就是个乘加），几十亿个连起来，就能学会语言。

AI 的"神经网络"和人脑的关系：**灵感来源，不是仿制**——形状像，机制差很远。

*核查：✅*

### TP2. ⚪ 词向量：文字变数字的魔法

模型不认识文字，认识数字。词向量（embedding）把每个词变成一串数字（比如 4096 个）。

魔法在于：**意思相近的词，数字也相近**——"国王"和"女王"在向量空间里是邻居。

这就是模型"理解"语义的方式：不是懂意思，是把意思变成了可计算的几何关系。

*核查：✅*

### TP3. ⚪ Attention：模型怎么"注意"重点

Attention（注意力机制）白话：读一句话时，模型给**每个词对其他词的"关注度"打分**——"猫追老鼠"里，"追"最关注的对象是"猫"和"老鼠"。

这就是 Transformer 的核心创新：**每个词都能直接"看到"句子里的任何词**（不需要像老模型 RNN 那样一个字一个字传话）。

长文本的处理、上下文的理解，全靠这个机制。

*核查：✅*

### TP4. ⚪ Transformer：现代所有大模型的骨架

2017 年一篇论文《Attention Is All You Need》发明了 Transformer——**现在所有大模型（GPT/Claude/Gemini/Qwen……）都是这个骨架的放大版**。

Transformer = Attention（互相看）+ 前馈层（消化）× N 层堆叠。

八年来架构的变化都是**微调**（更稳、更省、更长），没有革命。一个设计统治八年，在技术史上是罕见的。

*核查：✅*

### TP5. ⚪ 预训练：读书破万卷

预训练 = 给模型读海量文本（几万亿 token，约等于人类历史全部公开文字的几倍），任务只有一个：**预测下一个字**。

就这一个任务，逼着模型学会了语法、事实、推理、甚至一点点"常识"——因为要预测准下一个字，必须理解上文。

"大力出奇迹"的最佳案例：没人教它语法，它是自己从预测任务里"悟"出来的。

*核查：✅*

### TP6. ⚪ Token 化细节：BPE 怎么切词

Token 切分用 BPE 算法：**高频的组合合并成一个 token**（"the"是一个 token，"transformer"可能切成三段）。

中文的特殊性：常用字单独成 token，生僻字可能拆成字节——**同一个意思，中文和英文的 token 数不同**，这就是成本和窗口差异的根源。

训练自己的 tokenizer 是国产模型的重要功课——中文效率高一分，成本和速度都占一分。

*核查：✅*

### TP7. ⚪ 采样的底层：贪心、温度、top_p 的机制

模型输出每个字时，面对的是一个概率表。三种取法：

**贪心**（永远取最高概率——稳定但呆板）、**温度采样**（温度高=概率分布被"抹平"，冷门词有机会）、**top_p**（只从概率累积前 p% 的词里选）。

温度 0 不等于"绝对正确"——只是每次输出相同，错的还是错。

*核查：✅*

### TP8. ⚪ 幻觉的机制：概率的代价

幻觉的机制拆解：模型在训练时学到"这种问题后面通常接一段自信的回答"——**当它不知道答案时，它生成的仍然是"最像回答的东西"**。

关键认知：模型没有"不知道"的概念（除非训练过）——**概率机制没有"空白键"**。

这就是幻觉无法根治的原因：它不是 bug，是预测机制的自然结果。缓解靠 RAG（给依据）、训练（教它说不知道）、但对错混合永远存在。

*核查：✅*

### TP9. ⚪ 梯度下降白话：模型怎么"学习"

训练的本质是**梯度下降**：模型答题 → 对答案 → 算出"错多少"（损失）→ 算出"每个旋钮该往哪转"（梯度）→ 微调所有旋钮 → 重复几十亿次。

白话：像蒙眼调收音机——听杂音大小（损失），每次微调一下旋钮（梯度），几百万次之后杂音消失。

learning rate 就是"每次转多大"——转太大跳过最优点，转太小一辈子到不了。

*核查：✅*

### TP10. ⚪ 损失函数：模型怎么知道自己错了

损失函数（loss）是"错多少"的量化：模型的预测 vs 正确答案，差距越大 loss 越大。

训练的全部目标：**让 loss 变小**。

语言模型的 loss 是"下一个字的预测准确度"——所以模型的一切能力，都是从"预测下一个字"里长出来的。

*核查：✅*

### TP11. ⚪ 反向传播：错误怎么往回传

反向传播白话：发现最后一层算错了 → **顺着网络一层层往回推"谁的锅"** → 每个参数分到一点"责任"（梯度）→ 按责任大小调整。

这是深度学习能work的数学基础：**几十亿参数能同时被高效更新**，全靠这个算法。

显存的大头之一就是反向传播存的中间值——呼应微调系列 FT31 的 OOM。

*核查：✅*

### TP12. ⚪ 显存的账：参数/梯度/优化器的三倍定律

训练时显存的消耗 ≈ **参数本身 × 12**（参数 1 份 + 梯度 1 份 + 优化器状态 2 份 + 混合精度副本若干）。

7B 模型全量微调：70 亿 × 2 字节 × 12 ≈ 168G——这就是为什么全量微调劝退。

QLoRA 把参数压到 4bit + 只训小补丁——账单从 168G 降到 10G。**微调系列的所有"省显存技巧"，都源于这道数学题。**

*核查：✅*

### TP13. ⚪ KV cache：对话为什么越聊越慢

推理时模型会把之前 token 的中间状态缓存下来（KV cache）——不用每次重新算。

代价：**缓存随对话长度线性增长**——聊得越长，每个新字的速度越慢，显存占得越多。

这就是"长对话后模型变慢变傻"的部分技术原因——不是模型累了，是缓存大了。管理长对话：定期开新会话。

*核查：✅*

### TP14. ⚪ 位置编码：模型怎么知道词的顺序

Attention 本身不知道词的顺序（"猫追狗"和"狗追猫"在它眼里一样）——**位置编码**给每个词打上"位置戳"。

长文本的难点就在这：位置编码对"没见过的位置"泛化差——这就是长上下文需要 RoPE 扩展（FT80）的原因。

*核查：✅*

### TP15. ⚪ MoE 深潜：专家混合的机制

MoE（混合专家）机制：一个大模型内部有很多个"专家子网络"，每个 token 只激活其中一两个（由一个"路由器"决定）。

效果：**总参数很大（知识容量大），每次计算量小（只激活部分）**——671B 参数只算 37B 就是这么来的。

代价：所有专家的参数都要装进显存（显存不省），训练的负载均衡是工程难点。

*核查：✅*

### TP16. ⚪ RLHF 的数学：奖励与策略

RLHF 的数学白话：**策略**（模型的行为）产生**回答**，**奖励模型**给回答打分，**强化学习**调整策略让高分回答的概率变大。

KL 惩罚：限制新策略别离原模型太远（防止"为了高分变成疯子"）。

DPO 的聪明之处：把这个三步过程简化成一步——直接从偏好对学习，数学上等价但工程简单十倍。

*核查：✅*

### TP17. ⚪ 推理时计算：思维链的机制

推理模型的"思考"机制：回答前先生成一段**内部推理文本**（草稿），这段草稿作为上下文帮助最终答案。

为什么有效：**模型的每一步预测都更强，把难题拆成一串简单步骤后，每步都在能力圈内**。

这就是"测试时计算"——同样的模型，多给思考 token，正确率上升（呼应 MM17）。

*核查：✅*

### TP18. ⚪ 蒸馏的机制：软标签的秘密

蒸馏的核心是**软标签**：老师模型不只给正确答案，还给每个候选的概率分布——"答案 1 概率 70%、答案 2 概率 20%"。

学生模型学的不只是"正确答案"，还有**老师的不确定性结构**——这就是为什么蒸馏的学生比直接标注训练的更强。

暗知识（dark knowledge）这个词，说的就是概率分布里藏的教学信息。

*核查：✅*

### TP19. ⚪ 量化的数学：为什么 4bit 还能用

量化 = 把 16bit 的参数压到 4bit（16 个值砍到 16 个代表值）。

为什么掉点少：**模型的参数分布很集中**（大多数参数挤在小区间），4bit 的 16 个代表值足够覆盖。

NF4 的聪明：这 16 个代表值不是均匀分布的，是按正态分布的分位点设计的——**按数据的真实形状切格子**。

*核查：✅*

### TP20. ⚪ 混合精度：fp16 与 bf16 的数值差异

fp16 的问题：指数位太短，**大数溢出、小数消失**——所以要配损失缩放这套补丁。

bf16：指数位和 fp32 一样长——**范围不缩水，只牺牲精度位数**。训练稳如老狗，不需要补丁。

结论重申（呼应 FT40）：**能 bf16 就 bf16。**

*核查：✅*

### TP21. ⚪ batch 的意义：为什么批量更稳

单个样本的梯度是"噪音"（一个样本的观点），一批样本的平均梯度是"共识"——**批量越大，每步更新越接近真实的下降方向**。

但 batch 太大有反效果（泛化变差）——有效 batch 的甜蜜区间是工程经验 + 数据特性共同决定。

gradient accumulation 让小显存模拟大 batch（呼应 FT19）。

*核查：✅*

### TP22. ⚪ 过拟合的数学：训练/验证分离的原理

过拟合的数学本质：模型开始**记住训练数据的噪音**，而不是学习规律——训练 loss 降，验证 loss 升，两条线分叉的那一刻就是过拟合起点。

这就是为什么 train/val 必须分离（FT59）——**用训练数据验证自己，等于让学生用课本考试。**

*核查：✅*

### TP23. ⚪ 正则化家族：给模型戴紧箍

正则化的家族成员：**weight decay**（参数别太大）、**dropout**（随机丢弃防共谋）、**数据增强**（多见世面）、**早停**（见好就收）。

它们的共同目标：**让模型学规律，不学噪音**——泛化能力的来源。

*核查：✅*

### TP24. ⚪ 梯度消失与残差连接

深网络的古老难题：梯度往回传时**层层衰减**，传到第一层已经消失——深网络训不动。

残差连接（ResNet 发明，Transformer 继承）的解法：**每层加一条"直通车道"**（输入直接加到输出）——梯度可以走高速直达第一层。

这就是为什么网络能堆到几十层上百层。

*核查：✅*

### TP25. ⚪ 归一化：稳定训练的隐形功臣

归一化层（LayerNorm/RMSNorm）：把每层的数值拉回稳定区间——**防止数值在层层传递中爆炸或消失**。

Transformer 用 RMSNorm（比 LayerNorm 更简单更快）。没有它，深网络训练直接发散。

最不起眼的组件，往往是训练稳定性的关键——工程里到处是这个规律。

*核查：✅*

### TP26. ⚪ 激活函数：非线性的来源

激活函数（如 SwiGLU）给网络注入**非线性**——没有它，一百层线性变换叠加还是线性（等价于一层）。

**非线性的层数 = 模型能学的复杂度**。激活函数的选择是小细节大影响——SwiGLU 比 ReLU 的效果提升是实打实的。

*核查：✅*

### TP27. ⚪ Scaling Law：大力出奇迹的数学

Scaling Law（规模法则）：模型能力随**参数、数据、算力**的投入按幂律提升——投入越大，能力越强，可预测。

这个定律是整个大模型军备竞赛的理论基础：**先算账，再烧钱**。

2026 年的修正：数据质量、合成数据、推理时计算（MM17）——scaling 的维度从"一个"变成了"多个"，但底层逻辑没变：**可预测的投入产出**。

*核查：✅*

### TP28. ⚪ 涌现能力的争议

涌现能力（小模型没有、大模型突然会了）的争议：**是真涌现，还是评测方法的假象**（不连续的指标造成的视觉突跳）？

主流修正观点：换连续指标后，很多"涌现"其实是平滑提升——**但个别能力（如多步推理）的跃迁可能是真实的。**

对你的启示：别赌"下一个模型会不会涌现出我需要的能力"——**用能力已验证的模型。**

*核查：✅ 争议为公开学术讨论。*

### TP29. ⚪ 架构演进史：RNN 到 Transformer

大模型的前身 RNN 的致命伤：**串行处理**（一个字一个字传话）——慢、且远距离信息衰减。

Transformer 的革命：**并行处理 + Attention 直连**——训练速度和长距离理解同时解决。

历史的意义：2017 年之前的 NLP 模型全部被淘汰——**一个架构创新淘汰一个时代**。下次架构革命（如果有），同样的剧本会重演。

*核查：✅*

### TP30. ⚪ 开源模型的训练配方

开源模型（Llama/Qwen/DeepSeek）的训练配方公开程度：架构公开、数据配方部分公开（数据混合比例是各家最守的秘密）、训练细节部分公开。

"数据混合比例"是开源模型最后的秘方——**同样的架构和算力，数据配方决定成败。**

这也是为什么"数据配方"的论文和泄露，每次都是圈内大新闻。

*核查：✅*

### TP31. ⚪ 推理优化的数学：KV cache 与 PagedAttention

推理优化的两大发明：

**KV cache**：缓存历史 token 的中间状态，避免重复计算（TP13）。
**PagedAttention**（vLLM 的核心）：像操作系统管内存一样管 KV cache——**碎片化消失，吞吐翻倍**。

这两个发明让"推理服务"从不可能变成生意——呼应部署运维系列 DM4。

*核查：✅*

### TP32. ⚪ 投机解码：用小模型给大模型打草稿

投机解码的聪明：**小模型先快速起草稿（猜几个 token），大模型一次性验证**——猜对了就白赚，猜错了大模型重算。

效果：输出速度提升 2-3 倍，结果完全一样（验证保证正确性）。

原理的启示：**大小模型的协作不只是分工，还有"草稿与验证"这种高级玩法。**

*核查：✅*

### TP33. ⚪ 多模态融合的机制：图片怎么进语言模型

图片进入语言模型的机制（呼应 MM1 深化）：视觉编码器把图切成小块（patch），每个 patch 变成一个"视觉 token"——**图片变成了一串特殊的外语**，语言模型当它是一种没学过的语言来处理。

这就是为什么图片吃 token、为什么多图注意力分散、为什么视觉编码器的质量决定 VLM 上限。

*核查：✅*

### TP34. ⚪ 安全对齐的机制：拒绝是怎么训练出来的

模型"拒绝有害请求"的机制：对齐训练让模型学会**把有害请求的模式识别出来，然后输出拒绝模板**。

微调破坏护栏的机制（呼应 FT213）：微调的梯度更新会**顺带调整安全相关的参数**——哪怕你的数据无害。

这就是"微调后安全测试要重做"的技术根源——护栏不是焊死的，是画上去的，擦一擦就淡。

*核查：✅*

### TP35. ⚪ 模型的"性格"从哪来

同系列不同模型的"性格差异"（一个严谨一个话痨）来自：**训练数据的选择**（喂什么长什么样）、**对齐的偏好**（奖励模型喜欢什么风格）、**系统提示词**（出厂设置）。

用户可改变的部分：提示词和温度——**能调的是语气，调不了的是三观**（三观在训练数据里）。

*核查：✅*

### TP36. ⚪ 模型为什么"健忘"：会话的隔离

模型"忘记"之前对话的机制：**每次 API 调用是无状态的**——上一轮的内容要你主动传回去，模型才知道。

"记得你"的产品功能 = 应用把历史对话每次重新塞进上下文。

这就是为什么"换个设备/隔天再聊"就忘了——**记忆在客户端，不在模型里**（除非产品专门做了记忆存储）。

*核查：✅*

### TP37. ⚪ 上下文长度的代价：注意力的平方

上下文长度的成本是**平方级增长的**：Attention 要让每个词看所有词——长度翻倍，计算量翻四倍。

这就是长上下文的工程难点：**百万 token 窗口需要海量的工程优化**（稀疏注意力、滑动窗口、分层）。

实用推论：长上下文不是免费的——**用多少付多少，包括时间和钱。**

*核查：✅*

### TP38. ⚪ 分布式训练的白话

多卡训练的白话：**每张卡拿一部分数据（或一部分参数），各自算，定期同步**。

同步是瓶颈（卡越多，同步开销占比越大）——所以多卡训练的效率不是线性增长的。

这就是 DeepSpeed/FSDP 存在的意义：**让同步的代价最小化**（呼应 FT50/51）。

*核查：✅*

### TP39. ⚪ 评测的数学：为什么分数会饱和

评测分数饱和的数学：二元选择对的概率最高 100%——**当模型达到 95%，剩下的 5% 可能是题目本身有歧义**。

这就是为什么前沿评测不断"出新更难的题"（GPQA、FrontierMath）——旧题已经测不出差距了。

对你的启示：**看新评测的首发成绩，比看旧评测的刷分更有信息量。**

*核查：✅*

### TP40. ⚪ 收束：原理知识的实用价值

技术原理 40 篇收束：学这些原理的实用价值清单：

**调参时**：知道每个参数动了会怎样（不是死记，是理解）

## 进阶篇（TP41–65，10/1）

### TP41. ⚪ Embedding 空间的几何：相似就是距离近

"国王 − 男人 + 女人 ≈ 女王"不是段子，是词向量空间的几何事实。

原理一句话：训练后，**语义相近的词在向量空间里靠得近，语义关系对应方向**。性别、时态、单复数这些抽象关系，都对应空间里稳定的"方向箭头"。

这就是 RAG 检索的工作基础：你的问题和相关文档在空间里距离近。理解了这个，就理解了为什么"换个更好的 embedding 模型"能直接提升检索质量。

### TP42. ⚪ RMSNorm vs LayerNorm：归一化的代际

现代大模型几乎都换了 RMSNorm，为什么？

LayerNorm 做两件事：减均值、除标准差。RMSNorm 砍掉第一步，只做"除以均方根"——计算更少，效果几乎不掉。

砍得掉的依据：研究发现归一化的核心作用是**控制向量长度**（稳定训练），减均值是可有可无的附加动作。

工程课：先找到真正起作用的那一步，再砍掉仪式性的部分。

### TP43. ⚪ FFN 与 SwiGLU：模型的"思考层"

注意力负责"看别人"，前馈网络（FFN）负责"想自己"——它占模型参数的大头（约三分之二）。

现代 FFN 用 SwiGLU 结构：把一次变换拆成两条路，一条算内容，一条算"开关"（门控），相乘后再输出。

直觉：门控让模型学会"这段信息里哪些部分值得通过"。

为什么讲这个：看模型参数量时，FFN 的设计直接影响同参数量下的实际能力——这也是结构创新的必争之地。

### TP44. ⚪ GQA 与 MQA：注意力的省显存术

推理时 KV cache 吃显存的根子：每个注意力头都要存一份 K 和 V。

GQA 的解法：多个 Query 头**共享**一组 KV 头——比如 32 个 Q 头共用 8 组 KV，显存直接降到四分之一，质量损失很小。

MQA 更激进（全部共享），质量掉得多些。

这就是为什么"同一个模型"的 KV cache 大小不同——看架构表里的 KV 头数，别只看参数量。

### TP45. ⚪ 滑动窗口注意力：长文本的折中术

注意力平方增长的代价，一种务实解法：**每个 token 只看窗口内的邻居**（比如 4K），不做全局注意。

远处的信息不丢：靠"层叠传递"——第一层看 4K 邻居，第二层通过第一层的输出间接看到 8K，层层外扩。

适合场景：局部相关性强的任务（代码、长文档细节理解）。

代价：真正需要"远距离全局关联"的任务（全文总结）会吃亏。选模型时看它用的哪种注意力。

### TP46. ⚪ MoE 的负载均衡：让专家雨露均沾

MoE 的隐藏难题：如果路由器总把任务派给某几个"明星专家"，其他专家就荒废了，等于白养。

解法是**负载均衡损失**：训练时给"分配不均"加惩罚，强迫任务均匀流向各专家。

白话：学校里不能所有课都挤进一个老师的教室，要强制选课分散。

理解这个就理解了 MoE 训练的特殊性——不是纯让它学好，还要让它"公平地学好"。

### TP47. ⚪ Embedding 冷启动：新词是怎么学会的

模型遇到词表外的新词（新品牌名、网络热词）会切成碎片，理解打折。微调时怎么让它学会？

原理：新增一个 embedding 行（随机初始化），训练时梯度会把它拉到"语义上该在的位置"——周围语境的向量会"拽"它到位。

要点：新词要在数据里出现足够多次，且最好出现在**多样的上下文**里——就像人学新词，一次语境学不准，多处语境才牢固。

### TP48. ⚪ min_p 与 top_k：采样参数家族补全

温度和 top_p 之外，还有两个采样旋钮：

top_k：只在概率前 k 名里选——简单粗暴，k 定死了不会随分布变化；

min_p：只保留"相对最高概率超过阈值"的候选——聪明在**随分布自适应**：分布尖锐时候选少，分布平坦时候选多。

实践建议：创意写作用温度调；要稳定输出用 min_p（0.05 起步）——它比 top_p 在高温度下更不容易翻车。

### TP49. ⚪ Softmax：概率分布的诞生地

模型最后一层输出的是一堆"原始分数"（logits）， Softmax 把它们变成概率：**指数放大差距，再归一化**。

两个性质值得记：一是"赢者通吃"——分数差一点，概率差很多（指数的锅）；二是温度参数直接作用在这里——高温压平差距（更随机），低温放大差距（更确定）。

所以"调温度"不是玄学，是在调这个指数的放大倍率。看懂 Softmax，采样参数全通了。

### TP50. ⚪ 困惑度：训练日志里的体温计

读训练日志必会的数字：困惑度（perplexity）。

白话解释：模型对"下一个词"的困惑程度——它平均在多少个候选里犹豫。困惑度 10 = 平均在 10 个词里纠结。

用法：看趋势不看绝对值——同任务上困惑度稳定下降说明在学；突然反弹说明出事了（数据脏了/学习率炸了）。

陷阱：不同 tokenizer 的模型之间困惑度不可直接比较——"体温计"得是同一支才能比读数。

### TP51. ⚪ 词表大小的权衡：切得细还是装得多

词表 3 万还是 15 万？这是个三方权衡：

词表大 → 常用词整词保留，序列短（省 token），但 embedding 层参数暴涨；

词表小 → 参数省，但同样文本切得更碎（token 数多，推理贵）；

还有覆盖面：多语言模型必须大词表，否则小语种全是碎片。

中文用户选模型时看一眼 tokenizer 压缩率——同样是 100 万字，差的 tokenizer 能多收你一倍的钱。

### TP52. ⚪ 权重共享：tied embedding 的省钱术

一个安静的省钱设计：**输入 embedding 和输出投影层共用同一份矩阵**（tied embedding）。

原理：两者本来就是互逆操作——输入把 token 映射成向量，输出把向量映射回 token 概率。共用一份矩阵，参数省下一大块（词表大时尤其可观）。

代价：表达力略受限（一份数据干两份活）。

小模型几乎都 tying，大模型经常解绑——参数越多，越不在乎那点共享收益。

### TP53. ⚪ Continuous Batching：推理引擎的流水线

传统批处理像班车：凑够一车人发车，等最后一个人到站才算完——先到的干等。

Continuous batching 像地铁：有人下车立刻补位，车永远满载运行。具体做法是**每个生成步动态插入新请求、移除完成请求**。

这就是 vLLM 这类引擎吞吐量翻倍的核心原因之一（另一个是 PagedAttention）。

理解了它，就理解了为什么"换个推理引擎"比"换模型"便宜得多地提升服务能力。

### TP54. ⚪ 前缀缓存：系统提示词的折扣卡

你的系统提示词 2000 token，每个请求都要"重新读一遍"？前缀缓存说：不用。

原理：相同前缀（系统提示词 + few-shot 例子）的 KV cache 直接复用，只算新增部分。

两个实操点：一、把不变的内容放前面，变化的内容放后面——前缀命中率高，首 token 延迟和费用都降；二、部分厂商按缓存命中收费打折，长系统提示词的账单差距能到 10 倍。

排序即优化，成本敏感场景必做。

### TP55. ⚪ MoE 的容量账：总参数 vs 激活参数

看 MoE 模型的参数表会看到两个数：总参数（几百 B）和激活参数（几十 B）。

总参数 = 所有专家加起来（都得住显存）；激活参数 = 每个 token 实际用到的部分（决定计算量和速度）。

三个推论：一、MoE 模型对显存的要求按总参数算——"又快又能干"的前提是你装得下；二、推理成本按激活参数算——API 价格便宜有依据；三、本地部署选型时，MoE 是"显存换速度"的典型交易。

### TP56. ⚪ 数据的质量过滤：预训练的淘金术

预训练数据的主角不是"多少"，是"筛得多干净"。

主流淘金流水线：去重（相同内容只留一份）→ 质量打分（分类器判断"像书还是像垃圾评论"）→ 有害内容过滤 → 按来源配比。

有意思的研究结论：**数据质量的影响大于数据数量**——用精心过滤的 1T token 训练，可能好过囫囵吞 2T。

这对微调同样成立：500 条干净数据胜过 5000 条脏数据，是你早就该信的事。

### TP57. ⚪ RLHF 与幻觉：讨好目标的副作用

RLHF 有个反直觉副作用：**加重幻觉**。

机制：训练目标是"让评估者满意"，而评估者偏爱流畅、肯定、信息量大的回答。于是模型学会了一件事——**宁可编，也别空着**。说"我不知道"拿低分，自信地编反而拿高分。

后续的缓解方向：训练数据里加入"承认不知道"的正例、按事实性而非流畅性打分。

用户侧的自保：对过分流畅自信的长回答多留个心眼——那是被奖励出来的姿态。

### TP58. ⚪ 读 logits：模型的"自信度"怎么用

模型的原始输出 logits 是一座金矿，多数人只取了 top1。

三种用法：一、**置信度路由**——top1 概率低的问题才转人工或换更强的模型，省钱又稳；二、**多候选生成**——取 top5 自己重排，比让模型一次写五个好；三、**幻觉预警**——关键事实词的 token 概率突然走低，是模型在"猜"的信号。

前提：API 要暴露 logprobs（主流都有）。给你的 Agent 加上概率读数，等于给它装了仪表盘。

### TP59. ⚪ Lost in the Middle：上下文中间的盲区

长上下文研究里最实用的发现：模型对上下文**开头和结尾的信息记得最牢，中间部分最容易瞎**。

原因与注意力机制的位置偏差有关——首尾位置获得的"注意力配额"天然更高。

实操三招：一、关键约束写在提示词的开头或结尾，别埋中间；二、RAG 召回的相关文档，最重要的排在最前最后；三、超长上下文任务分段处理，别迷信"能塞下就能用好"。

塞得下 ≠ 读得进。

### TP60. ⚪ Self-consistency：让模型投票

一道难题让模型答一次就信？试试**投票**：同一道题采样 10 次（温度调高），10 个答案里出现最多的就是最终答案。

原理：推理链有对有错，正确答案会从多条不同路径反复到达，错误答案则各错各的——"众数"自动过滤了大部分错误。

代价：成本乘以 10。所以用在高价值题上（数学、关键决策），日常任务不值得。

这也是"模型并非只有一条思维路径"的直接证据——同分异构的推理世界。

### TP61. ⚪ 剪枝的数学：哪些权重可以扔

训练好的大模型里，大量权重接近于零——剪枝的赌注就是：**扔掉它们，能力基本不掉**。

两种剪法：非结构化（零散地扔，压缩率高但硬件吃不到红利）和结构化（整层整通道地扔，硬件友好但掉点风险大）。

近年趋势：剪枝的戏份被量化抢走了——量化"把每个权重变小"比"扔掉一部分权重"更容易被硬件支持。

了解即可：除非做边缘设备极致压缩，日常选量化和蒸馏就好。

### TP62. ⚪ GPTQ vs AWQ：两种量化智慧

同样压到 4bit，GPTQ 和 AWQ 的哲学不同：

GPTQ：**误差补偿**——逐层量化，每量化一个权重，用剩余权重"补偿"引入的误差，像精密的账目平移；

AWQ：**激活感知**——先观察哪些权重在推理时被"重要激活"用到（通常不到 1%），重点保护这几个，其余放宽。

AWQ 的洞察更聪明：不是所有权重平等，**重要的少数权重决定质量**。选型上两者都能用，AWQ 在对话类任务上常略优。

### TP63. ⚪ 推理并发的显存账：batch 与长度的跷跷板

推理服务的显存怎么估？两个变量在跷跷板两端：**并发数**（同时服务几个人）和**上下文长度**（每个人的 KV cache 大小）。

显存 ≈ 模型权重 + 并发数 × 单人 KV cache × 平均长度。

一个反直觉事实：上下文从 4K 涨到 32K（8 倍），能同时服务的人数就缩到原来的 1/8——**长上下文的代价不是变慢，是变少**。

容量规划先算这笔账，再谈优化。

### TP64. ⚪ 多 token 预测：一次吐两个字的野心

传统训练目标：预测下一个 token。新方向：**一次预测多个**（n-gram 预测头）。

两个收益：训练时信号更密（一次错多个地方，梯度信息更丰富）；推理时配合投机解码，一次验证多个 token，生成速度显著提升。

Meta 的研究显示多 token 预测对代码类任务提升明显——模式性强、可"提前算"的内容受益最大。

这也是"训练目标创新"重回舞台的信号：不只有堆参数一条路。

### TP65. ⚪ 线性注意力的尝试：Mamba 们在解决什么

Transformer 的原罪是注意力的平方复杂度，Mamba 等线性架构给出另一条路：**把"翻旧账"换成"记笔记"**——用一个固定大小的隐藏状态滚动压缩历史，复杂度线性增长。

收益：超长序列的处理成本大降，吞吐高。

代价：固定状态意味着"笔记"装不下所有细节，精确回溯（比如"第三段那个数字"）不如全量注意力。

现实格局：不是替代，是分域——全局理解用注意力，超长流式处理试试线性架构。混合架构（两者拼装）正在成为新旗舰的常见选项。
